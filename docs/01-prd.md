# 01 · 完整产品需求设计

本章描述完整目标，不设周计划或短期替代版本。机器可读需求与验收条件见 `specs/requirements.json`。功能域是界面与架构的组织方法，不代表必须同时启用所有高级功能。

## 1. 功能域

| 功能域 | 完整职责 | 核心对象 |
|---|---|---|
| Projects | 项目导入、Git/非 Git 空间、目录信任、worktree、归档 | Project、Workspace |
| Agents | 安装发现、版本、认证诊断、能力协商、兼容性 | ProviderInstallation、CapabilitySupport |
| Sessions | 受管交互、批处理、恢复、通知、快捷对话与任务关联 | Session、Connection、RuntimeEnvironment |
| Capabilities | Skill/MCP 发现、来源、差异、profile、受控同步与回滚 | Capability、ConfigSnapshot、ChangeSet |
| Tasks | 创建、委派、接力、并行、预算、取消、恢复、工作流 | Task、Attempt、Handoff、Workflow |
| Evidence | 代码/数据/报告产物、验证、审查、采纳、导出 | Artifact、Validation、Acceptance |
| Attention | 集中审批、阻塞、失败、冲突、未确认副作用 | AttentionItem、Approval |
| Settings & Extensions | 外部工具打开方式、版本更新、留存、诊断、provider扩展、远程主机 | Host、Integration、RetentionPolicy |

## 2. 项目与工作区

可导入现有目录，不默认执行安装脚本、不默认初始化 Git、不扫描整个磁盘。导入页分别确认读取目录、运行 Agent、写入工作区、诊断 MCP 的授权。Git 仓库显示当前分支、dirty 状态与工作树关系；数据目录同样是一等工作区，不要求每份数据入 Git。

一个 Project 可包含多 Workspace；每个 Workspace 的实际路径、host、Git base revision 或数据快照明确。移动目录后可重定位，不能仅按路径字符串误认同一项目。归档停止新任务但保留历史；删除本地记录与删除用户源文件是两个操作，默认绝不删源文件。

编码任务默认独立工作区，单写任务也不直接改原项目，并行任务分离worktree。非Git写任务需隔离副本/快照或受控输出目录。没有安全隔离路径时阻塞，不默认为原地写入。worktree是变更隔离，不是安全沙箱。

## 3. Agent 接入与诊断

正式目标：Codex、Qoder、Claude Code；扩展入口：自定义ACP，按能力分项开放。每种Agent可创建多个具名Connection，固定程序来源、配置所有者、身份引用、执行Host和支持矩阵。项目绑定默认连接，运行中不静默换账号、环境或计费。

托管环境默认由Baton准备兼容版本，允许复用本机路径。按已批准更新策略维护独立安装，新版本仅用于新任务，不修改全局安装。初次准备与认证通过App内引导；不要求用户逐Agent手写配置。实际下载、认证、SDK/ACP参数与许可须验证。[S05][S09][S10]

SupportManifest逐项覆盖启动、交互、事件、审批、取消、恢复、Skills、MCP、委派、配置隔离。某功能文档存在或adapter能启动，不等于完整支持。无法确认剩余额度或Token费用时显示未提供。

## 4. 会话管理

所有受管会话在Baton内发送消息、显示结构化过程、工具卡片、命令输出、Diff、产物和审批。ACP/原生/headless只是接入方式；托管配置/原生配置连接是配置所有权，不能混为一类。

主界面以任务组织；快捷对话可直接选Agent，转任务时保存已批准的上下文并补齐可验证合同。会话可搜索、标签、收藏、归档、重命名。没有原生事件时标明缺口，不猜测思考过程或虚构百分比。

独立后台持有进程和日志；关闭或退出UI不停止已授权任务。登录Mac后启动后台，另设停止任务并完全退出，注册透明可撤销。休眠/断网/崩溃后先对账再恢复。本机关闭不能承诺继续运行；远端运行与桌面连接状态分开。

## 5. 能力管理

用户必须能看到全局/项目/插件/启动参数等来源和覆盖关系；同名能力不能简单去重。Skill 的发现、启用、暴露、完整内容加载、使用证据分别表达；MCP 的配置、诊断连接、某会话连接和工具调用分别表达。[S05][S07][S08]

按 Agent、项目、profile 对比；查看冲突、来源 revision、依赖和变更影响。profile 不是权限沙箱；对不支持的能力不能静默忽略。

默认托管配置由Baton权威管理，原生配置连接只读。首次项目导入经检查合并一次确认，按批准规则生成不同Provider配置；不隐式继承外部用户能力。变更支持diff、备份、版本冲突检测、应用校验及回滚；新配置不自动改变活跃任务快照，安全撤销需专门处理。

## 6. 任务与工作流

提交目标后自动补齐项目默认上下文，生成可验收任务合同、计划与路由；目标/权限/预算/验收获批后，范围内自主拆解、委派、验证和返工，不强迫逐节点确认。具体输入、产物、版本和验收绑定。支持顺序、并行、条件与有界修订及模板。

交接可由用户操作、批准模板或 Agent 调用 Baton MCP 发起。无论入口如何，都进入同一 Task Router。委派权限不能由被委派 Agent 自己扩大；同一工作链限制深度、fan-out、活动尝试数和外部副作用。

工作流自动生成并展示依赖图，用户可调整步骤、执行者和验收条件、保存模板。计划修订要有版本，不能伪造历史或削弱验收。完整自由拖拽画布不属于批准范围；有界修订不等于无限循环。

## 7. 编码场景

例：Codex 实现解析器，Qoder 独立审查，Codex 修复，验证器运行既定测试。传递代码 base/head、patch、测试命令与报告，不以“另一个 Agent 说没有问题”作为唯一验收。

达到批准的验收条件后自动采纳、合入授权目标分支；集成候选需绑定目标head并重跑验证，更新引用前再次检查。目标dirty/保护规则不得绕过；禁止stash/reset/force覆盖用户改动。已授权推送、PR和测试部署自动进行，生产发布单独确认。

## 8. 数据分析场景

例：Qoder 检查数据分布，Codex 实现处理流程，再由独立脚本验证指标。输入记录 dataset 版本/哈希、schema、行数、单位、时区、随机种子和依赖环境；输出包含可复现脚本和机器可读结果。Agent 结论不等于科学正确性，关键统计假设与数值容差需要人或已批准验证程序确认。

大数据以引用交接，允许带标签的抽样。采样结果不得伪装成全量结论；文件修改使旧验证过期；跨 host 需要显式传输和敏感级别许可。

## 9. 结果审查与经验

一个任务页同时展示产物、差异、验证结果、审查意见、批准记录和未解决风险。验收与执行成功分离。经验沉淀生成候选模板/规则，产品负责人确认后才进入共享 Profile 或 Skills，不自动把一次成功提升为永久指令。

结果可以导出为脱敏 Markdown/JSON 证据包，标记来源和未测范围。完整会话与详细日志本地保存，按到期策略清理或永久保留；工作默认90天可调整，来源见D04，不删除源文件或采纳成果。原生未暴露事件标缺口，绝不采集外部全终端。

## 10. 非功能需求

关键事件可靠持久化；大量流式日志有背压与截断提示；UI 断连可恢复；配置并发修改不丢失；权限和凭据默认最小；无网络时仍可查看本地已保存记录；可导出用户数据并清理；界面支持键盘、读屏、深浅主题和中英文资源结构。

性能以不同并发数、日志量和项目规模建立测量基线，区分 Baton 自身资源与 Agent 进程资源。禁止在没有测试时写“低于 100 MB”或“毫秒级”保证。

## 11. 完整产品验收定义

所有批准需求具有实现、失败路径、测试和证据链接；所有正式支持 Provider 的版本矩阵通过；代码和数据接力能真实运行；设置变更与恢复无静默数据损失；生产包无测试后门；用户能在同一App主入口选择独立托管环境或显式原生配置连接；未知能力与缺失测试可见；发布包可追溯到通过验证的提交。

产品无需一次实现所有扩展 Provider 才能有价值，但完整设计中的需求不能因为一次任务预算不足而被删除。状态应保留为未实现、待确认或待验证。
