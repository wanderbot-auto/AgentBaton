# macOS job boundary and evidence contract

Original step 12 is the last stage in desktop. It reached 50:49 elapsed in the first cancelled run and 47:37 in attempt 2. Core/native alone took 40:26 and 36:44. Splitting only the default release and packaging leaves the observed cancellations in the first job. Keeping the genuine fresh18 gate in the second job gives the first job around 9–12 minutes of observed margin. [First job](https://github.com/wanderbot-auto/AgentBaton/actions/runs/44792307596/job/136482869813) · [Second job](https://github.com/wanderbot-auto/AgentBaton/actions/runs/44792307596/job/136778165181)

The second job starts after desktop and owns the existing required Product / macos-15 name. GitHub counts a conditionally skipped job as acceptable for required checks, so the required job uses needs plus always. Its first step fails unless the first job returned success and supplied a receipt. It compares the receipt with the pinned uploader ID and digest exposed separately by the first job. It checks the merge parents and current repository, workflow, run and attempt before product dependencies or acceptance run. A stale output from a partial rerun fails even for the same checkout. Manual dispatch records a separate diagnostic identity. [GitHub required-check behavior](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks#handling-skipped-but-required-checks)

The source receipt records the actual Darwin/arm64 platform, Git tree, commit, PR parents, PR number, main base and merge refs, along with the GitHub repository ID, workflow path/ref/SHA and exact run/attempt. The core-complete step checks the observed start context, eleven successful step outcomes and the artifact ID and digest. The release phase recomputes the same identity before executing, before development upload and after uploads. Its final log binds the three distinct artifact IDs and their SHA-256 digests. Review outputs using those IDs and the run and attempt. Existing artifact names may repeat across attempts. Verify the development ZIP and its four entries, DMG hash, build record, architecture and audit independently before acceptance. [Pinned upload action outputs](https://github.com/actions/upload-artifact/blob/ea165f8d65b6e75b540449e92b4886f43607fa02/README.md#outputs)

The early runner uploads only the known finite tool, migration and rework report paths. It retains bounded failures without emitting a success receipt. The second runner builds its own frontend and release tools from pinned source. It does not download the first job's executable files, database, private history or runtime. The original native tools and case definitions run serially from the second runner. The Integration collector and native upload still run after observed native failure when the release source check passed. If release admission failed, the first runner's artifacts carry the diagnostics.

A 30-minute second job has an estimated 24:46 reference using the earlier successful 14:01 tail plus independent setup and cold build costs of about 1:45, 2:52, 2:26 and 3:42. This mixes observations across runs and is not a guarantee. Require one complete eligible workflow against the exact integrated Git tree and unchanged checks, inspect the logs and artifacts, and measure both real margins. The first deadline stays 60 minutes and test, child-process and migration bounds remain as before. Timing and uploaded artifacts under the new graph have not been observed.
