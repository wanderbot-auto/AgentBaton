# ADR: separate untrusted renderer endpoint snapshots

The retained PR19 Product41183987127 normal case stopped at the original `expect(owner).to_be_enabled()` after CG01/CG02. The successful exact Goal get was an intermediate read. Existing v3 deliberately has no UI epoch/fresh/loading/pending source. One typed readonly Busy reply has no Owner-window attribution. The specific failed gate or refresh stage remains unknown; the separate local normal PASS does not reclassify that CI failure.

V4 adds `owner_ui_state` beside the unchanged v3 payload. The default `FiniteRuntimeDiagnostics` still produces v3. Only this real browser harness explicitly selects its v4 subclass. The projector validates the unchanged legacy payload through the original v3 validator, then validates the additional closed fields. The original PASS predicate is unchanged.

The panel emits its already-held renderer epoch, fresh/loading/pending kind and unknown bit, capacity, connected, busy, cancel-reading, base disabled, view presence, summary freshness and existing parent readiness props. These are attributes only, with no visible implementation wording or new API. No live/graph guard is recomputed for diagnostics. The Owner review button has a fixed marker; the collector reads its actual DOM disabled property. A base gate can be distinguished from a missing or disabled Owner control, but the exact live/graph subcondition is still unobserved.

The harness makes one `evaluate_all` read before the original refresh click and one in the original enabled-expect finally block, before closing the same diagnostic window. It adds no wait, retry, click, timer or deadline. The original 5s expect, 15s context, 20 readonly reads at 1000ms, TTL, runtime budgets, Owner gates and cleanup remain unchanged. DOM protocol overhead is real and is not claimed to be zero; the expectation budget itself is not renewed or enlarged.

Each read requires one currently connected panel with the fixed v4 marker and one existing Goal history whose private `data-run-id` matches the original expected Goal. The ID is used for a private equality check only and is never returned. Duplicate/missing/foreign components, absent/oversized/unknown attributes, mismatched button marker/caption, DOM-read exceptions and malformed scalar values yield a whole unobserved endpoint. At most one review control is accepted. An absent review control is an observed false presence only when the panel/history/attributes are valid; it is not a disabled control. False stays false, never null. Duplicate endpoint submissions permanently invalidate that endpoint. Public malformed/unknown fields or timestamps outside the original diagnostic window are refused.

Each endpoint is a bounded fixed-key object: epoch is an exact nonnegative JavaScript-safe integer; boolean attributes accept only exact lowercase strings; pending is one of the existing five intent kinds or none; unknown is bool only when pending exists. No raw IDs, paths, text, error strings, DOM HTML, requests or credentials are published. Fields are labeled `renderer_local_untrusted`, authority `none`. A rendered epoch can lag a ref change until render, and remount/transition lineage is not established. Two endpoints do not prove continuous state, refresh completion, click causality, authorization, business success or stop. Missing intermediate changes remain unknown.

A complete three-file inverse removes only reviewed fixed additive layers and fixed opt-in/marker insertions, verifies each layer SHA, and reproduces the entire b3 original files by SHA. Unknown changes outside or inside a layer fail the source controls. Mounted controls separately exercise a deferred initial-plan tail after successful Goal get, an old view during manual refresh, a superseded epoch, an unready parent with fresh base state, and ignored diagnostic DOM tampering. These are mocked renderer controls, not real Core/Native/CI evidence.
