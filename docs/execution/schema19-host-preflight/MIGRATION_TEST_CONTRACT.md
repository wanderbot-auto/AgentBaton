## Exact19→18 TEST-FIXTURE inverse

Provide separate standalone and caller-owned-transaction functions. Standalone requires autocommit and uses one Immediate transaction; in-transaction helper requires an existing transaction and does not commit, toggle FKs or start a nested BEGIN. A separate read-only19 validator validates genuine migration results without modifying/downgrading them.

Before the first DROP/PRAGMA write, require all of:

1. Exact integer user_version19 and a complete known schema19 reference derived from preserved18 plus only approved Host DDL. Expected Host table, all table columns/checks, SQL bytes, PK/UNIQUE autoindexes, named index and outgoing FK must match. Missing is not empty.
2. Host table is actually empty; no Host-domain `host.registered` event or `hosts.register:v1` receipt remains. Also reject any unknown/future `host.*` event kind or `hosts.*` receipt scope, malformed Host envelope or ambiguous domain reference; an empty table alone is insufficient. Bound scans and validate namespace/JSON consistently; ambiguous or corrupt documents reject. Never erase evidence to manufacture emptiness.
3. No unknown Host-prefix object, extra/missing index, Host trigger/view, incoming FK from any other table or unexpected dependency/reference; arbitrary extra table/view/trigger must reject when not part of a declared caller sentinel. Existing original sentinel/collision tests can declare their exact additional non-Host object explicitly and preserve it; no wildcard allowance. Run FK/integrity checks and verify the entire retained schema against its known reference plus that exact sentinel.

Only then remove the approved empty Host objects and set18. Compare all retained schema/rows/rowids/raw content, events/idempotency/receipts, counters/application_id/FK invariants. New tests must independently mutate each object/column/check/index/FK, add Host record/event/receipt/dependency, omit Host table, add extension, corrupt DB/JSON, use integer18/20 or a wrong schema, and force a late caller failure. SQLite user_version itself is integer; float/string/bool type negatives belong to JSON reader/collector boundaries, not an invented floating PRAGMA fixture. Every rejection leaves the complete original19 image unchanged. No product IPC, startup recovery or real user DB may call this helper.

Refactor into new explicit19 wrappers; do not nest the standalone inverse or commit Host first. Original18 and16 helpers continue rejecting19. Intentionally failing the last caller step must roll back Host, Conversation, Integration and Factory changes to the original19 snapshot.
