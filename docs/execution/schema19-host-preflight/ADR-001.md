# ADR-001 — Separate current19 compatibility from historical18 evidence

Status: proposed for leader/B agreement; static audit only. Source: accepted `a4e03303b54bd5a5544131e95ad39662f8310e29`. This ADR grants no source ownership.

Use the existing Core Store, event journal and idempotency transaction. Host registration is immutable, create-only metadata; no second DB, companion journal, connection row, Grant, identity directory, SSH invocation, host contact or execution routing is introduced. Declared platform/path and opaque references are syntax declarations, not observed facts or authority. Preserve all current local-only execution filters. Builtin `local` is not a writable registry row.

Proposed exact new DDL (final bytes must be agreed and pinned before implementation):

```sql
CREATE TABLE host_registrations(
 id TEXT PRIMARY KEY,
 name TEXT NOT NULL,
 name_key TEXT NOT NULL,
 revision INTEGER NOT NULL CHECK(revision=1),
 created_sequence INTEGER NOT NULL UNIQUE REFERENCES events(sequence),
 document TEXT NOT NULL
);
CREATE INDEX host_registrations_name_id ON host_registrations(name_key,id);
```

`name_key` is the server-produced stable sort key, initially trimmed name without a new case-fold/uniqueness policy; names may repeat, UUID ids distinguish records. `name`, `id`, `revision`, event sequence and the strict versioned document must agree when read. `created_sequence` references the actual SQL `events.sequence` assigned by INSERT, never the serialized Event.document.sequence (existing event constructors serialize0). Verify event aggregate_id/kind/revision, Host mirrors and idempotent receipt together in the same transaction/read contract. The document contains server-generated created timestamp, metadata and explicit unverified/not-contacted/disabled facts. The one outgoing FK is to the existing event sequence; opaque identity/config/known-hosts digest references have no FK to unrelated Provider/Connection domains. There are no Host triggers/views, execution-authority FKs or new sqlite_sequence counter. Primary/UNIQUE autoindexes are included in exact schema comparison; they are not extra SQL statements for schema-cookie counting.

The proposed namespace is `hosts.register:v1` in the existing `(scope,key)` idempotency table, with event kind `host.registered`. In one Immediate transaction: validate bounded closed request; lookup exact key/body replay; enforce bounded registry count; generate id and event; insert Host with that event sequence; store exact idempotent receipt; commit. Any failure rolls back all three domains. Same key/body returns original record/sequence; different body conflicts; lost response is reconciled read-only before retry. No fabricated remote status is persisted. No schema migration emits registration events/receipts.

The event FK has default NO ACTION, with no CASCADE or SET NULL: a live Host registration pins its creation event. This phase adds no Host deletion, history deletion or automatic retention operation. A future authorized history-cleanup implementation must retain referenced creation events or introduce a separately reviewed lifecycle/archive relationship; it cannot silently delete Host metadata, sever the receipt/event binding, or turn off FK checks. A missing/orphan/corrupt creation event or receipt is an integrity failure, not an excuse to erase the Host. This retention dependency and the proposed namespace/record bindings must be agreed in B's documentation contract before product wiring.

Schema19 activation is a coordinated compatibility change. Store upper bound19, a distinct pre-v19 backup, migration and exact19 reopen verification must land with all current readers/handshakes/producers. API protocol1 and record format1 remain separate. Old authenticated daemon18 is rejected by the existing snapshot handshake; `ensure_daemon` must not launch a second daemon on a version mismatch. Unknown outcomes and users' original DB remain available for reconciliation/export/restore.

The product reference describes every known authority-bearing object, not every historical user object. Preserve accepted `integration_store::compatible_schema:140–217` opaque compatibility: ordinary non-FK/non-generated tables and their safe ordinary-column indexes remain uninterpreted data, with complete original rows/DDL retained; unknown triggers/views/authority indexes/dependencies still refuse.63→64 counts the trusted reference/fresh known-domain fixture, not the entire arbitrary user DB. The test-only inverse below deliberately has a stricter exact-extension policy; do not import that restriction into product migration/reopen.

The original Conversation18 DDL/migration and original18→17,17→16,16→older test helpers remain exact historical contracts. Add a separate test-only19→18 layer and caller-owned current19 composition wrappers. Preserve old helper bodies, inputs, frozen sources and before/after hash pins. Reject unknown/partial/extra source bytes and mixed schema inputs. This is never a product downgrade endpoint.

## Native lifecycle helper has two roles

`scripts/native-run.py` is both a current18 native report validator and the historical lifecycle helper hashed by genuine14/15/16 producers. `prepare-legacy-migration-fixture.py:65–73,328,371` loads/hashes it; `factory_child_goal_legacy_migration.rs:84–89`, `task_workspace_actual15_migration.rs:449–450` and `integration_actual16_migration.rs:518` compare the manifest against its exact included bytes. Directly editing this file would invalidate existing historical evidence even if all lifecycle functions stayed equivalent.

Prefer preserving that complete file and its original tests/hash. Propose a separate `scripts/native-run-schema19.py` for the current19 native validator/run entry and dedicated tests, with exact lifecycle-equivalence evidence. Current `native-macos-smoke.sh:26,31` and `native-linux-smoke.py:59–62` must use that explicit19 entry; macOS's import of report validators must change too. The historical producer continues using the unchanged old helper. `native-owner-dialog-smoke.py:298,322–340` imports only the old owned-lifecycle functions, which remain valid and unchanged. Do not silently monkeypatch shared module globals or loosen old source hash sets. The implementation of the new entry remains subject to independent review; this is a proposed path, not tested code.

The actual reuse boundary is `native-run.py:225–259`, `owned_group_is_quiescent` and `owned_child_exited`: these functions contain no schema validation. The full `run:262–377` is **not** schema-neutral:364 invokes the old `native_report_error`. Therefore the new19 entry must not call that old run/validator with a disguised18 report. If its owned-run loop is versioned/copied, preserve exact original lifecycle source/AST equivalence for262–354 (including original time bounds, signal-before-reap and Linux descendant cleanup) and independently verify the new19 report-validation tail. Original artifact/report bytes stay19; only source-code inverse tests reconstruct historical18 source bytes. These are different evidence dimensions.

Preserve original source inverse manifests/functions as inner layers. Add a separately pinned19→accepted-a4-source adapter at current source-reading entry points. A new complete19 source hash plus exact edit spans must reconstruct the complete original a4 file SHA before any old18/notification/fixed-script/phase/post-join inverse executes. Already-original source may pass only its exact original pin. Never search Git, discover source dynamically, accept arbitrary suffixes, regenerate old pins from the candidate, or interpret a grep count as proof.

One Host table plus one named index changes current63→64 tables and adds two explicit DDL cookie increments. Genuine15's existing12 increment becomes14; with an extra sentinel table current64→65 while predecessor17 remains60. Old55/59/63 references, old cookies/backup proofs and original SQL bytes remain historical. If leader changes this proposed DDL, counts and the exact inverse/test contract must be revised together before activation.
