# Factory boundary choices

Status: implemented candidate, pending independent review and real Core13 integration. Baseline0e2860f; decisions follow Root/Core technical contract confirmations, not new authority.

- Owner Renderer has seven fixed wrappers; the Agent's four scoped MCP tools and private credential-file path/token never enter renderer commands. Native Factory approval is a separate kind, full1MiB bounded UTF8 pages plus final genuine CallerOwner confirmation; old single16KiB kinds and Graph kinds remain unchanged. Share only the existing lossless page splitter.
- Initial Factory approval/start is Draft-only. Root/Core rejected treating arbitrary old OutcomeUnknown plus owned reaping as reconciliation. Private already-authorized parent continuation is a new attempt after explicit handoff; renderer does not mint that context. Scope/grant IDs and revisions are separate; Factory task-splitting limits do not mutate Grant derived-grant depth/children authority.
- Renderer round-trips only safe-number selections and CAS. File-system u64 identity metadata is opaque; never stringify/rebuild its digest, compare rounded pins or send it back. Only safe business selection fields are fingerprinted. Native Rust preserves every original serde Value/u64 in full review/result binding. Full original binding display would require a separate raw-text contract, not an invented renderer reconstruction.
- Revoke/cancel request does not prove process stop or effects known. A per-task confirmed_stop proves only that task's latest owned attempt; a waiting relation's parent_stop_confirmed applies only to its referenced old session. No resource-release/actual-usage claim exists without Core projection. Current RunDetails has no usage ledger: show approved bounds, not fabricated meters. Completed Factory processing never implies TaskAccepted.
- Read all scopes/runs for the root before replacement authority; revoked/expired records with live/blocked/unknown runs keep new execution closed. Monotonic immutable-scope and run floors reject stale/forked/missing records; historical exact-key receipts may acknowledge their operation without regressing fresh floors. Any failed recovery preserves the ORIGINAL unknown, even if the current recovery dialog was declined/not_started.
- Default folded Details entry, no homepage/navigation change and no Factory RPC before expansion. Bounded20 readonly polls1s while active/open then explicit pause notice/manual refresh; no automatic mutation. Pending exact intent/key/CAS retained within UI process across remount. At64 contexts evict only idle nonpending history; never evict unresolved/active state; exhausted memory makes a new context read-only instead of crashing/forgetting unknown operations.
