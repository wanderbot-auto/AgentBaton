# ADR — Parent read generation with a complete semantic source token

The original ChildPlans callback depended on scope/target references; every parent read published equivalent new objects and triggered a second withdrawal/read. Removing that trigger without replacement would hide MCP-only plan revisions. A later passing actual diagnostic observed two disabled windows with equal head/raw; it did not reproduce or prove the old CI52 no-dispatch cause.

Decision: increment a mount-local private read generation at each original parent refresh start. ChildPlans schedules its unchanged full context/list/head/raw-hash verification on generation plus complete semantic parent identity/scope/target/run/connection state. Equal clones in the same cycle cannot trigger another read, but every original cycle still discovers new history. Epoch and current-source token reject stale async results. A synchronous reading ref also blocks a submit before React commits a read-start state update. New writes require original freshness plus matching verified token and original trusted read identity, all original parent/live/state/cancel/draft guards and action-time approved-scope/Grant expiry. This bookkeeping is not authority.

A stable current-props ref avoids stale callback closures while preserving the exact source context used to validate a committed receipt. Same-business read-only descendant provenance remains distinct from write readiness. Historical exact-key recovery retains its existing narrow unknown branch and original raw/key/CAS. No intent lock, poll freeze, automatic write/retry or generic scheduler is introduced.

Submission notice is separate from read error. Local parse/definite denial/unknown survives background reads. A guard rejection creates no pending operation or API request and says this intent sent no new request; an existing pending unknown stays unknown. Notices clear on appropriate explicit editing/confirmed receipt/submission actions, not on read success. English/Chinese private notices remain in the component to avoid broad i18n/API edits in this narrow scope.

Limit: a disabled native button may swallow a gesture before React receives a click; this implementation cannot promise notice for an event it never gets. It addresses deterministic duplicate read churn and actual silent function returns, not a proven repair of CI52 or a reason to lower CP08 acceptance.
