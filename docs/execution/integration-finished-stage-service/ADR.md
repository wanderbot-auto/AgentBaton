Status: selected, source-only; performance benefit not measured.

Root's exact777 real IPC14 run passed13 and failed the existing three-round positive. Retained round1 preparation1452/2000ms and validator2004/2000ms triggered the unchanged RESOURCE_LIMIT guard. Actual Command exited0 with false target-drift validation, within Command budget, real reap/EOF. The89s suite duration is not a stage breakdown. The existing queued-at clock includes real join, readonly postprobe and Actor proof; no part may be omitted or frozen.

The existing daemon services the full Factory and Goal frontiers before its ordinary integration pass. An original stage can have genuinely finished while waiting for those passes. Add two opportunities to service such an owned completion: immediately before the Factory scan (after the existing supervisor/owned-worker/finish-read/fatal-error handling), and between Factory and Goal. A cheap nonserialized observation of the current OwnedStage's real JoinHandle::is_finished is the sole new gate. A true gate calls the complete original tick_stages; it does not construct a receipt, skip live checks, settle from a hint or scan armed policies. A false gate performs no database reads or writes. Retained unknown/not-scheduled work is left to the original full pass; it is not replayed through the new gate.

The original full Factory→Goal→integration pass, including the original armed-policy order and mandatory full Goal stop sweep, remains in place. The ordinary integration path still checks current stop/fence/lineage, consumes the actual join, verifies original proof/deadline, meters the original queue clock, settles fees and unknown fences, and uses normal full next-stage read/admission. No policy, active-worker exclusion, schema, permission, reservation, wall/cleanup clock or public IPC changes.

Tradeoff: a genuine completion may start the next already-approved stage earlier, so that next stage's queue clock can include later scans. The net result is not guaranteed to improve, and no claim is made that Factory/Goal scans caused the observed2004ms.
