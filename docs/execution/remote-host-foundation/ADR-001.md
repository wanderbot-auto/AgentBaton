# ADR RHOST-001: bounded Host foundation v1

Status: implemented foundation; integration acceptance remains with leader. Base b78ffbb5bcbe741de2e0cd8fcf2e568c4c7ef28c. No root workspace/IPC/schema/desktop/CI changes.

## Transport and trust

The release direction is system OpenSSH with strict host-key verification, explicit user/identity and a private, digest-pinned known_hosts registration. The trusted registration associates expected Host ID with key file digest/alias, hostname, port and user. Client rejects a different protocol Host/recipient before sending bytes. Self-reported Host fields and host echo are not authentication. Local tests use private pipes and generated disposable identities; they do not prove encrypted transport or cross-machine compatibility.

`/usr/bin/ssh -F none -T` disables ambient user/system SSH config. Explicit options enforce StrictHostKeyChecking=yes, UpdateHostKeys=no, private known_hosts, GlobalKnownHostsFile=/dev/null, publickey-only BatchMode, one identity, no identity agent/certificate discovery, no forwarding/local commands/multiplexing; connect timeout 5s, one attempt, server-alive 2s × 2. Unknown/changed host keys must fail in OpenSSH. File digest drift is rejected before launch. No automatic key acceptance, identity copying, network listener or account discovery exists. IPv4/DNS names and allowlisted absolute paths only in v1; IPv6, jump hosts, hardware/interactive authentication need a separately reviewed extension.

Remote command is exactly `exec /usr/local/libexec/baton-host-companion --serve <approved-absolute-config>`; no RPC payload enters SSH argv or the remote shell. Path characters are limited to ASCII alphanumeric `/ _ - .`, with dot/traversal segments refused. SSH joins command arguments through a shell; this allowlist and fixed executable are necessary even with local parameterized argv.

Official references checked 2026-11-17: [OpenSSH ssh(1)](https://man.openbsd.org/ssh.1) and [ssh_config(5)](https://man.openbsd.org/ssh_config.5). The manuals describe remote command joining and config precedence/strict checking. Installed macOS system version: OpenSSH_10.3p1, LibreSSL 3.3.6. Generated-key `ssh -G` tests check effective local configuration without a login. Actual SSH host-key rejection/handshake is **not_run**, pending an approved Host; argv tests and digest drift tests do not substitute for that evidence.

## Provisioned authority and immutable execution binding

Owner/Core must provision a private local configuration via an already trusted installation/control path. This crate does not supply a remote Grant/renew/root RPC or bootstrap UI. Configuration must be an absolute canonical non-symlink regular file, owned by effective UID, single hard link, ≤32 KiB, mode 0600 or stricter, in a canonical private owned directory. State and mapped record directories must be canonical owned private directories. Existing SQLite files/sidecars must also be private owned regular single-link files. Opened root is checked with fstat, compared with path metadata, and its device/inode persist with Host/binding identity. Replacement at the same path is drift. This is not an OS sandbox or protection against a hostile same-UID process/kernel; the provisioner and local account are trusted. No native global file is changed.

Grant binds Host, project, named connection, attempt, input revision, effective configuration revision, identity reference, logical mapping, data recipient/sensitivity, controller, fence, operation permission, operation/byte budget and absolute issue/expiry. Message auth uses a fresh scoped credential; only its SHA-256 is provisioned/persisted. Credentials are carried only in the private pipe/SSH channel, never receipts/events/logs. No Provider identity material is copied. Host ID/key registration must be approved by Core, not by an Agent message.

Root project budget enforcement remains a Core integration dependency. In this foundation one provisioned attempt's ledger is shared by its workers and controller epochs; a new fence never resets usage. Monotonically narrowed ceilings prevent a higher fence broadening the existing operation/byte grant. There is no task/delegation API to obtain a separate budget. Cross-attempt/project shared budgets require the future Core budget authority; do not infer that this isolated crate enforces them globally.

A greater fence can be installed only by replacing trusted local configuration and opening a companion. It retains fixed binding/root identity, cumulative usage, cancellation and revocation; invalidates unresolved prior-epoch work to outcome_unknown. Every job also persists dispatch fence and exact grant digest, so a delayed worker cannot adopt a renewed lease. Stale configs/controllers are rejected. No request renews a lease. Renewal is explicit local reprovision, not reconnection.

UTC milliseconds use validated nonnegative SQLite INTEGER; maximum lease horizon is 300s. Every worker uses monotonic elapsed time plus wall expiry and durable highwater. Wall time is sampled *after* obtaining the journal writer lock. A backward clock durably pauses effects; cancellation, revocation and reconciliation remain possible. Restart/reconnect with the same lease conservatively pauses, since monotonic continuity cannot be proven. Reconcile and receipt replay remain available; new effects need a newly provisioned higher fence. A disconnected controller is never a reason to extend a lease or migrate an attempt.

## Protocol and actual bounded operation

Private newline-delimited UTF-8 JSON v1; unknown versions/fields/actions are rejected. Identifiers: ASCII alphanumeric/underscore/hyphen, 1–64 bytes. Frame ≤32768 bytes; partial-frame/read and response/write deadlines 2s. Idle stdio polling is distinct from partial-frame timeout; idle does not cancel a task. SQLite busy timeout 500ms; maximum journal 8192 pages (normally 32 MiB), 10000 events (96 settlement slots reserved before new-effect admission), 4096 receipts, 32 jobs; events replay in pages of 64, records ≤4096 bytes, ≤5000ms scheduled delay. Every collection and request has a fixed bound. No generic shell, terminal, directory sync or arbitrary command API exists.

Actions: Reconcile(cursor), Record(name,content,delay_ms), Cancel, Revoke. `Record` is a real restricted foundation capability, **not remote Provider execution**: an owned companion child creates a single UTF-8 file under the preapproved remote mapping. Names are leaf identifiers, not local paths. Descriptor-relative openat(O_EXCL|O_NOFOLLOW), mode 0600, file and directory fsync prevent overwrite and symlink traversal. No source file is removed. Arbitrary coding tasks/Provider operations must later use a separately integrated executor under the same authority contract.

Each envelope repeats the fixed binding, expected Host, controller/fence and idempotency key. Duplicate key/same fingerprint replays the receipt; a changed payload/controller/epoch conflicts. New epochs should use new request keys. A receipt says Accepted/CancelRequested/Revoked, never implies completion. Errors expose only stable code names (identity_binding, unauthenticated, stale_controller, expired, clock_rollback, paused, permission, budget_exhausted, idempotency_conflict, protocol/version, oversize/half_frame/timeout, journal/capacity/path etc.), not secrets or private OS errors.

## Durability, uncertainty and stop proof

SQLite FULL synchronous transactions atomically reserve budget, persist job intent, receipt and event **before spawn**. File effect plus journal cannot form a single cross-resource transaction: a crash or journal failure after create/fsync remains outcome_unknown. Reserved/running intents are never automatically redispatched on reopen. Exclusive create and durable receipts prevent overwrite/repetition; this is not a global exactly-once promise. Budget reservations are conservative and are not refunded for failed/unknown effects.

Worker cooperatively checks lease/fence/pause/revoke/cancel between bounded steps and immediately before effect. The supervisor owns child handles, polls/reaps while serving, and on EOF drains approved work rather than canceling it. Drain has a 6s supervision deadline, then kills and waits owned children; Client closes stdin and waits up to 8s before killing its own transport group and joining the transport. A kernel operation stuck in uninterruptible IO cannot be promised a hard stop; the protocol must retain unknown until real stop evidence exists. No PID from a stale journal is used to kill an unrelated process.

`cancel_requested` survives independently on controller and Host journals. The persistent controller Ledger queues an offline cancellation without storing credentials, reconstructs a fence-specific request when credentials are supplied, and deduplicates events/cursors. Received cancellation is not confirmed stop. Only the supervisor's actual child ExitStatus/wait, or a distinct spawn-failed-no-child result, supplies stop evidence. An orphan/whole-group crash is unknown after reopen; absence of a handle/PID does not fabricate success. Cancel is idempotent; unknown past effects remain unknown even when no further process effects can occur.

Reconnection first replays bounded ordered sequence/cursor events for the same attempt and validates Host/binding/fence. Client forbids new Record until the last reconciliation page. Ledger rejects gaps, conflicting repeats, out-of-order/stale epochs and forged stop projections; replay does not duplicate stored events or regress newer projections. Link loss is a transport state, never automatic task failure/new attempt/migration.

## Data and integration boundary

Record bytes go to the approved Host/mapping and remote journal/cache. Input revision, recipient and sensitivity are fixed metadata; caller must classify/approve data before transmission. No claim that bytes stay on the Mac. The controller journal is a local event/reconciliation cache; product main history remains Core's local primary. Remote retention is explicitly pinned until Core project-retention integration exists; no automatic purge/export/source synchronization is implemented or claimed. Do not send real confidential project data through this development foundation without that integration and policy approval.

Follow-up integration must supply reviewed Host registration/provisioning, shared root budgets, executor/native engine, Core event history/cache retention, router and UI, lifecycle/service installation, cross-machine macOS/Linux evidence and SSH handshake tests. Those changes are outside this task's write scope. This standalone workspace is **not discovered by root cargo/CI**: run scripts/verify-remote-host.py explicitly.


## Leader-review capacity accounting

New Record and trusted higher-fence installation retain the original 96-slot admission reserve: after their event commits, at most 9904 events exist. At most 32 admitted jobs can each still owe one worker terminal event and one actual supervisor wait (or the alternative spawn-failed-without-child event): 64 slots. First Cancel and first Revoke each need one slot (2), and a necessary same-lease reopen/unknown-state transition needs one (1): worst-case 67, within 96, leaving 29 slack. Remaining debt is counted separately: every job without stop evidence needs one wait slot; only reserved/running/effect_intent jobs additionally need one worker-terminal slot. A terminal event consumes its slot and removes that debt before the pending wait is recorded; outcome_unknown needs only its potential future wait. Budget/intent counters are never reset or refunded.

Controls and existing-epoch opens use the remaining settlement reserve calculated from outstanding wait and worker-terminal debts, not the 96-slot new-effect admission gate or an unrestricted zero reserve. First control transitions reserve the other outstanding control, all worker/wait evidence and any required reopen. A control already durably true can issue a new bounded receipt without appending another identical state event; same-key fingerprint replay/conflict is unchanged. A same-lease reopen appends an event only if pause or unresolved job projection actually changes; otherwise a repeated paused open adds none. An internal worker Store::open(config,false) uses settlement accounting without inventing an admission/metadata event. Worker terminal, spawn-failure and real-wait writes independently check the unchanged 10000 hard ceiling; duplicate stop registration adds no event.

The regression seeds the equivalent reachable 9903-event state of alternating same-lease pause and separately trusted local higher-fence provisions, then tests Record→9904, first Cancel/Revoke in both orders, blocked additional Record, receipt replay/new-key coalescing, actual child stop→actual parent wait, and same-lease reconcile/reopen. It is not a claim that ordinary short RPC traffic naturally reaches this history. The 32-job/4096-receipt limits remain unchanged; this finding does not establish first-control receipt exhaustion in normal traffic or change that policy.

The additional 32-job regression seeds 9872 reachable provisioning events, admits 32 real records through event9904, runs all 32 owned children to durable terminal state before recording any wait event (9936), then records first controls in both orders (9938), all actual wait statuses (9970) and necessary reopen (9971). This catches over-reserving terminal debt after it has already been paid. All files and consumed operations remain32, with no reset or redispatch.
