# Asynchronous data reads and authoritative creation records

`DataWorkspaceSelection` declares only a registered project ID, explicit relative regular-file requirements and bounded limits. Source root comes from the Project. The host chooses managed root, destination and IDs. Actual hashes and root/file identities are computed from generated or owner-selected local files; declaration, observed snapshot and trusted copy authority remain separate types.

Preview is asynchronous and read-only. Copy needs independent native kind `data_workspace` approval of the exact snapshot and destination. A single SQLite transaction consumes the owner proposal, inserts creating workspace/creation and owner/prepared journal commitments. Only then is the single bounded I/O thread scheduled. Post-commit refusal reports the recorded intent and existing creation; confirmed refers to that approval/intent, never to copied bytes or Ready. A later uncertain database failure remains unknown.

No thread writes SQLite. Slow copy/hash/restore and data-root JSON/integrity validation use one bounded domain worker. The actor consumes a private, non-deserializable observation for one exact authenticated request and deadline, then clears it. Root, selected file and publication-marker descriptor/stat observations are rechecked at handoff. This is point-in-time verification, not continuous freezing against same-UID processes. Goal data inputs currently select actual native-approved dataset-copy files; arbitrary later output artifacts cannot borrow this witness. Goal plans/ready are planning only and never dispatch or accept work.

Private runtime exclusion uses its held directory descriptor and actual device/inode in addition to canonical location checks. A generated renamed/replaced runtime cannot become an ordinary dataset. This recognizes Baton-private state, not arbitrary sensitive data: there is no DLP, whole-HOME authorization or OS sandbox claim.

Creating/Ready marker bytes alone are never trusted. Authoritative rows bind complete snapshot, managed/destination pins and contract, consumed owner result and source-checked positively ordered owner/prepared/finished event IDs. Ready restore rehashes only the approved isolated selection and does not revisit an original source that may have moved or been deleted. Extra workspace outputs are permitted; selected input replacement or mutation is rejected. A later writer epoch blocks earlier artifact validation.

Cancel only requests cooperative stopping. Chunk boundaries and markers check cancellation/deadline; a blocked kernel I/O call cannot be forcibly interrupted. Only actual thread join produces `worker_joined`; panic/unknown filesystem outcome remains unknown. A partial directory is retained without cleanup, overwrite or automatic retry. An interrupted creation without a persisted trusted root/completion cannot be promoted from its marker. Shared model/project/root budgets are neither initialized nor reset by preview/copy.

Limits remain explicit: 64 inputs, 64MiB each, 256MiB total, source path at most 16 components/4096 bytes, 100 records and 4MiB raw aggregate per project/domain list. The private `inputs/` prefix can add one internal component, but complete destination path budget is checked before reservation. Those source-selection limits do not silently narrow existing Git artifact contracts. Complete64-file owner proposals are retained; a separate native display implementation must satisfy its unchanged16KiB complete-review bound without losing fields.
