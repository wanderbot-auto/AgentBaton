# Preserve a bounded ancestor admission sample beside a recorded advance intent

Status: source implementation, awaiting independent review and real Rust/Store verification.
Baseline: `e874b123d3e7f329a551e21922baf1a7a643548f`.

The existing ancestor reservation guard constructs a finite optional `factory-ancestor-budget-v1:` diagnostic. After a recorded Goal advance intent, IPC overwrote that original reference with `recorded-goal-advance:<intent_id>`. Consequently the existing `goal.run_blocked` event could not recover its already-supported optional `budget_admission` sample through this path.

Keep the exact leading legacy marker and add only the versioned suffix `|budget-admission-v1:<JSON>` for a complete, bounded original ancestor refusal. The strict four-field private JSON contains `run_id`, `run_revision`, `intent_id`, and the unmodified `original_guard` string. The complete reference is at most 4096 UTF-8 bytes; the original guard JSON is at most 1024 bytes. Decode rejects duplicate, missing, extra, wrong-version, malformed, foreign-run/revision/plan/intent, and oversized values as a whole. The nullable original metric fields must be present; observed null is distinct from absent data. An existing complete raw guard remains supported. Invalid or unavailable optional samples leave the original refusal and exact old recorded-intent wrapper behavior intact.

The pure production error wrapper receives the actual seven-field receipt already returned by admission, the selected run, and the requested run revision. It preserves the original error fields, including the existing `not_started` to `confirmed` normalization. Real admission records an event and receipt but does not advance the run revision; its original ledger request must not be compared to IPC's subsequently updated ledger revision. The receiver checks current run/plan revision before adding the finite sample to the original blocked event; normal save then increments the run revision.

`details_ref` remains an opaque optional diagnostic reference under the public error contract. Repository search at this baseline finds one `recorded-goal-advance:` producer and no parser, but that does not establish absence of external consumers. Keeping the leading legacy marker minimizes disruption; consumers must not parse undocumented suffixes as authority. Private wrapper IDs do not enter the finite public event projection. The repeated canonical intent UUID detects inconsistent binding; this is not an independent database existence proof, receipt authentication, or execution authority. No new lookup, durable record, SQL, RPC, event, migration, cache, permission, or budget action is introduced.

This restores observability only. It must not change caps, declaration sizes, queue charges, deadlines, rejection order, retries, or blocked-state acceptance. The failed Intel e874 case remains failed. Its post-join child total 14029 plus next declared reservation 6000 exceeds a possible 20000 cap by 29 ms, but the original guard did not survive; that is a candidate explanation, not a proved original decision. No original failure evidence is rewritten.
