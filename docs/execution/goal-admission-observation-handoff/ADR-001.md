# ADR-001: Keep diagnostic ownership in the existing private reply

Status: implemented source, independent review and runtime verification pending.

A second diagnostic channel would need coordinated delivery, another receiver and two queues per Goal request. Instead the existing ReadyRequest reply is a crate-private enum: ordinary socket/Factory lanes retain SyncSender<Value>, while the already-owned automatic Goal lane retains SyncSender<GoalAdvanceReply>. The latter envelope holds the unchanged wire Value and one optional opaque sample. All original bounded channels/capacities and timeouts remain. Ordinary try_send(Value) keeps its existing TrySendError<Value> shape; only the two normal dispatch completion sites send an observed envelope. Early errors remain diagnostic-free.

The dispatch handler captures the bounded original sample on its stack before applying the original recorded-goal-advance reference/confirmed-effect transformation. No externally received JSON can supply the opaque envelope, whose sample has no Clone/Serialize/Deserialize. The same pending Goal receiver delivers both fields. At the original block_goal_run transaction, sample run ID/revision/plan and bounded closed fields are checked against the current run; missing/foreign/stale samples add no diagnostic and never change the original blocked transition or grant authority. The old optional details_ref decoder still handles its original paths.

Do not encode both diagnostics and recovery refs in the public details_ref string, add fields to public CoreError, retain a global mutable cache, introduce extra diagnostic writes, or move the original budget guard/block state transition. A full Actor scheduling/timing test remains separate from the new actual Core/SQLite composition tests.
