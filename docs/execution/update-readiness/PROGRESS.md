# AB-REL-007 进展

- 实现 `Store::assess_update_readiness` 和 `Store::recheck_update_readiness`。从现有 Core schema 19 读取任务、派发、会话、Goal、Graph、Factory、验证、集成、工作区及持久化写入栅栏。未知状态、未释放栅栏和待确认取消均拒绝就绪。
- 后台可用、可信确认已停止和无法观察分别报告。调用方还须从可信 actor 提供非 Provider 本地工作和远端执行覆盖。现有 `BackgroundStatus` 只覆盖 Provider 活动，已向集成窗口报告正常入口的补齐依赖。
- 核对开发批准的版本、平台、commit、候选包摘要和目标 schema。备份证据绑定当前 Store 边界，迁移样本绑定本备份和候选，恢复样本是独立的精确备份还原。实际文件按 SHA-256 与只读 SQLite 核验。
- 就绪戳固定输入证据、数据库水印、背景实例与文件身份。候选、无事件的 SQLite 漂移、活动或背景实例变化都会导致重查失效。
- 本阶段不拥有切换执行权。后续 actor 需补齐全部运行观察、持有独占维护边界、停接新工作并在真正切换前重查。真实安装、签名、自动更新服务、生产发布和跨版迁移合成另行验证。
- 先期独审指出同名数据库被替换时，路径和既有连接可能代表不同文件。用实际文件换位复现误报后，改用同一 SQLite 连接的 Unix VFS `SQLITE_FCNTL_HAS_MOVED` 检查，并在水位读取前后比较路径身份和外部数据版本。缺失或异常反馈阻塞。保留修前红日志。
- 自查补齐实际 Graph 作业的 `completed` 已结状态，并阻塞尚未结清的 Goal 和 Factory 预算、缺失的 Factory 停止证据，以及关键持久状态与索引不一致。
- 历史 `session.turn_ended/outcome_unknown` 保留阻塞。现有消息回执确认、进程停止与 Goal 特例回执还没有可解除该历史未知副作用的持久对账记录。后续正常入口需按确切会话、尝试与 turn 核验处理，单独停止或后续成功不足以清除。
- 最终实现通过 9 项定向与 16 项既有回归。真实合成会话验证任务运行、取消待确认，以及成功完成一轮、由 Supervisor 结清并确认停止、重新生成匹配的备份证明后就绪。格式、编译和严格 Clippy 通过。
