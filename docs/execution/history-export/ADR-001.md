# ADR-001 · frozen history package v1

Status: implementation contract · 2026-11-17.

| Source | Ownership | Export projection |
| --- | --- | --- |
| projects | exact selected id | id/name/revision only |
| tasks | bounded documents; project_id matches selected id | id/project_id/goal/state/spec_revision/revision/timestamps |
| sessions | project column AND document project/task mirrors; task must belong | id/task_id/project_id/state/revision/attempt_id/timestamps |
| conversations | project column AND document mirror | id/project_id/title/state/revision/attempt_id/timestamps |
| events | aggregate_id in verified project task/session/conversation ids; payload project_id, if present, must match | envelope plus allowlisted normalized payload; raw/config/auth/opaque values excluded |

All counts and documents captured in a single SQLite read transaction. Sequence range applies to journal only; entity metadata is current at snapshot. Journal bodies are available normalized local capture only; no Provider completeness claim. Excluded global/other-project events are counted without exporting ids/content. Artifacts, raw protocol, external references, auth, runtime configuration, recovery/idempotency, approvals, source files and database image excluded. Missing raw/artifact references counted, never followed.

`history_exports.preview`: strict selection v1 (project_id, from_sequence exclusive, to_sequence nullable inclusive, tasks/messages/events flags) -> immutable preview id, selection digest, package SHA-256, counts, cutoff, exclusions and redaction report. At least one category. Scan up to 10,000 entities/events, input 4 MiB, single record 256 KiB, 2 second capture deadline; fail explicitly without truncation. At most 64 retained directory entries (a published preview uses two entries) (no automatic deletion in this scope).

Snapshot is a private fixed-format JSON package containing manifest, logical JSON files with SHA-256 over exact UTF-8 content, and report. Manifest marks history-only/non-restorable. Filesystem work runs on one owned, joined worker so fsync does not block the daemon loop. Private fs uses anchored directory descriptors, O_NOFOLLOW, ownership/mode checks, create-new files, fsync, and hard-link atomic no-overwrite publication. IDs are canonical UUIDs; no renderer paths. A partial `.writing` is never consumed. Package SHA-256 binds preview to execute, filenames/content hashes bind files. Snapshot remains unchanged while live history advances.

`history_exports.publish` and `.get`: only preview_id, selection_digest, package_sha256; inspect existing result first, verify bytes, never overwrite. A lost response is reconciled via get then same original publication. Restart works from private on-disk preview. Publication does not mutate SQLite. `history_export_reveal` verifies the same controlled result, then fixed `/usr/bin/open -R` argv on macOS, no shell/arbitrary file/program capability. Reports are observations, not an OS security sandbox against a malicious same-uid process.

No general redactor exists at this base (providers README explicitly says unimplemented). Add export-local audited allowlist, omit auth/config/raw fields, recursively remove credential keys, suppress text containing credential markers, redact recognized token-shaped words. Free text cannot be guaranteed secret-free; UI and report warn before publication. No native identities/paths copied.
