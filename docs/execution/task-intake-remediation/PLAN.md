# AgentBaton 任务启动整改单

审计基准为受保护的 `origin/main`，提交 `145a5041e93f82778167de28ac8aebbc4b795cd5`。样本是一个已导入的 Git 项目。用户提交「修复一个失败的测试，并用项目现有测试命令复验」。

**整改目标**。项目策略已经覆盖的常规任务，从一次明确的启动进入后台执行。系统补齐能确定的信息，并以任务状态说明正在准备、排队、执行，或需要用户作出的具体决定。

## 实施顺序与边界

1. 先交付 START-01 的后端首批。入口以已经确定的工作区、连接、授权和修订为输入，以 daemon 记下的状态和回执为准。本批不会自动创建授权。涉及新迁移或其他共享契约的需求须由对应写入者与集成窗口协调。
2. START-02 依赖受控的项目默认策略，以及前端窗口依据固定契约接线。项目策略可以选择有效授权范围内的执行路径。现有绑定无法覆盖新工作区时，应由后台提出具体授权差异，或在已有项目权限提供安全委派的前提下派生权限。
3. START-03 到 START-05 分别保有测试和接线依赖。前端重构窗口管理 UI 和对应测试文件。最终接线需使用真实 Core IPC 验证。
4. 受保护 `main` 的合并、全局 STATUS、需求台账和 CI 由指定集成窗口管理。生产发布、真实 Provider 身份及调用、额外付费仍适用 AB-START-001 的独立边界。

关联要求为 AB-TSK-001、003、004、007、008、009、010、011、012，AB-PRJ-004、005，AB-SES-002、006、008。业务规则沿用 D03、D11、D15、D17、D18、D20。

## 整单验收

- Apple Silicon 上用真实本地 daemon、SQLite 和生成的 ACP 测试进程覆盖正常启动、不同键并发重复、未授权及过期/漂移拒绝、取消以及重启后的未知结果处理。
- 桌面验证覆盖已配项目的一次启动、资料不足时的单一下一步、保留草稿、连接或预算失效和等待执行槽。保留确切提交及各维度证据。
- 保持已批准资源预算、会话绑定、受保护分支检查和回执恢复。真实厂商账号和原生交互的验收分别记录。
