# 工作流进度

初始工作树干净，固定基线及认领已回报集成窗口。确认旧 workflow 在 Data Workspace 后才写 schema 18 候选，而所有现行运行路径要求 schema 19。Task Workspace 工具复制、Child Goal 三案编排和 Integration 有限投影可复用。Native 工作流原有整份摘要入口需追加字面认领，已发给集成窗口。

新增候选生产入口保留现有 build 命令和单独的 debuginfo 设置。CI 在浏览器消费者前复制两件只读工具并写出一致的两份清单字节。Integration 从同一份清单和前端记录制作私有副本，探针在真实设备通道、类型化快照和所属进程回收均通过后封存八字段。按集成窗口复核后的第 11 条认领接回 Native 历史逆向。第一次定向测试保留了提前退出 mock 排序错误，已按真实观测顺序修正。

第一轮实际工作流构建和预览合同通过，本地镜像缺 `ensurepip` 使原 venv 命令失败。补齐镜像依赖后，现行链路实际发现旧 Goal Planning 默认系统 Chromium 路径不存在。这一轮的 Integration 探针也因本地 Mac 绑定目录无法 chmod Unix socket 而正确拒绝，有限投影保持红。保留各轮失败。下一固定源码将显式传递 Playwright 的真实 Chromium，并让 Integration 同时复验原始 Core 构建记录。局部演练将 RUNNER_TEMP 放在 Linux 容器文件系统上，以满足原有 socket 权限。

两轮同源全链保留五条 Child Goal 失败。分别验证两轮 Integration 两案与有限投影，详见 EARLIER_WORKFLOW_EVIDENCE.json。真实浏览器只读观测证明父 Task 的实际修订先于界面。初始启动时渲染从 draft/r1 更新到 running/r3。Owner 点击时 Core 已到 outcome_unknown/r4，界面仍是 running/r3，随后渲染更新。生产状态变化的拒绝正确。保留产品守卫，驱动改为在原 5 秒按钮可用窗口内，用已收到的真实 Core 响应和当前可见父 Task 修订对齐。新定向控制保留变更前缺少观测门槛的红结果。开始、Owner 及取消过程原有 15 秒、单次写与其恢复规则均保留。
