# Registered directory context is observation, not execution authority

The API accepts a closed project-source/managed-workspace selection with canonical UUIDs and positive exact u64 revisions. Source versus isolated target is preserved in the reflected selection. Caller filesystem paths, environment, programs, arguments, hosts, credentials and Grants are absent. The new method is available only through the existing authenticated Owner route, never a Factory companion method.

The registry has no host field in Project/ManagedWorkspace: these are its existing local records. A remote field in the closed selection is refused rather than inventing a host capability. Project sources have no separate ready-state field, so a source requires a valid current non-archived registration and matching actual directory identity. A managed target additionally requires exact project membership, project/workspace revisions, state ready and a recorded identity. Normalized row columns and bounded stored documents must agree. Reads use one existing-connection deferred transaction; only two parameterized bounded SELECTs are possible and no records/events are written.

Opening a directory is distinct from admitting execution. It does not inspect Git HEAD/cleanliness, Git metadata, file contents or data-copy evidence, reserve a lease, assign a task, reuse an execution candidate or transfer approval. Dirty Git and ready data directories are supported. Existing downstream input/validation and write gates are untouched. Archived sources and pending/unknown/unpinned managed records are refused.

The path must already have the exact absolute normal-component spelling recorded by the registry. No canonicalize/symlink or alias fallback is performed. Each component, including root, is opened read-only with O_DIRECTORY|NOFOLLOW|NONBLOCK|CLOEXEC; every descriptor remains held. The maximum is 129 directory identities (root plus 128 components) and 32768 path bytes. Held metadata produces canonical decimal u64 device/inode strings; no JS-number round trip occurs. Held and freshly named chains are compared before returning a context and again by the public Native helper. All private error messages are fixed and contain no raw filesystem/SQL/credential values.

The public `pin_open_context` validates a context's shape, exact path, identity lengths/decimal forms and actual root-to-leaf correspondence, then returns `WorkspaceOpenDirectoryPin` with `recheck()`. It does not authenticate a context: Native must fetch it from the original Owner connection and compare its selection. File descriptors and identity rechecks are observations, not atomic lifetime pathname immutability, a filesystem sandbox or a lease. Kernel filesystem calls may stall despite NONBLOCK; no new interruptibility or product time budget is claimed.

The existing Owner Request decodes params into serde_json::Value, which folds duplicate nested keys. The new method therefore needs the private raw-envelope check supplied in the Root-only hook patch: after existing typed envelope parsing, only an authenticated Owner whose final method equals workspace_open.context gets a second strict decode with typed params. It covers the same seven existing Request fields; write-envelope fields are explicitly forbidden even when null. All other routes retain their original bytes/semantics. No global parser or IPC refactor is proposed.

Unit registry fixtures intentionally model ready data/Git records without claiming those creation workflows ran. The Unix IPC Git positive uses the actual public workspace creation path and generated Git; its data positive is explicitly a typed ready data registry fixture. Tests assert read/refusal preserves every retained row and zero execution-domain counts. Test source and Linux results cannot establish actual Native/macOS directory handoff or a real Provider interaction.
