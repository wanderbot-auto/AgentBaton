# ADR: false validation is history, target-only proof is narrowly bounded continuation

Status: Root-approved implementation choice; no additional product authority. Root/independent contract review identifies a safe but missing D19 recovery path. Stable-target failure is still terminal. Existing cwd_file/verify_current/PASS and both CAS all-pass gates are unchanged.

The opaque library observation is deliberately not a pass or an authority token. It independently checks the original expected exit list (including legitimately approved nonzero exits), natural timely exit, original cleanup cap, actual leader reap/EOF, no truncation/cancel, image/program/script/input/output identities and hashes, exact clean candidate and direct commit target slot. A peeled tag, symbolic slot, changed input/output/image, late/cancelled/unknown command, or unsupported metadata tree supplies no usable recovery proof. Full source/accepted/Native-policy/GoalScope/Grant/definition/fence/current-descendant proof is a separate owned readonly Core observation, under the same original ticket/absolute deadline/cancellation epoch. No JSON object can reconstruct either private handle.

The read path shares the original raw DB descriptor owner using Arc, and keeps it owned across worker panic/join and Actor settlement. It does not open/close another untracked raw DB leaf in the Actor transaction. Declared output pins are opened only in the worker and retained; Actor metadata checks use held descriptors/no-follow stat. The owned command is retained before every fallible postprobe. Active Drop still cancels, truly joins and disposes context before releasing DB ownership/writer lock; a consumed join must not set cancellation merely because its former owner is destroyed.

A proof is checked before sampling the original queue clock. Actual false validation receipt and original fees remain even if postprobe fails. An unknown postprobe cannot refund/settle unknown usage or release its unknown fence. Only fresh successful target-only verification plus unchanged policy mode/max-round/expiry/cancel/overrun/remaining shared-budget checks may queue another complete preparation. The final context is fresh, and the old false receipts never enter final CAS correctness authority. The first two false receipts and third true receipt imply seven Integration stages, not two invented CAS effects; original Graph adds one consumed attempt.

Recovery witness limits are explicit fail-closed limits, not a reduction of full product scope: 8192 tree entries, 256 directories, 1MiB cumulative stored names/relative paths, depth128; rejects unsupported symlink/special/multi-link recovery trees. Ordinary non-recovery validator support remains unchanged. Regular filesystem syscalls cannot be promised preemptible; real join/unknown ownership rules remain. Mac program-ancestor metadata coverage is source-reviewed, not an actual Mac ACL test. Unknown escaped descendants are not represented as enforced containment. FullVAL009 and platform validation remain open.

Review correction: retaining one Arc is insufficient if reseal opens and drops a different raw FD for the same inode. The narrow private builder accepts the already held DatabasePin; both the post-validator read and the existing in-transaction own-transition reseal use the same descriptor owner. This is a source closure of the explicit DB-pin lifecycle contract, not a claim that a POSIX lock loss was dynamically reproduced.
