# ADR — Factory-derived Goal execution

Native Factory scope gains a separate complete child_goal_execution_policy and server-resolved binding. Existing child_planning snapshots remain plan-only and omitted fields retain old serialized bytes. No implicit Grant revision or ceiling amendment is allowed. Original max_children/max_depth and actual cumulative remaining root/project/ancestor usage constrain launch and every attempt; children=0 never becomes a new independent Goal root.

Factory-derived authority has an explicit provenance record pointing at the real consumed Native Factory approval and immutable saved plan reference. It is not a fabricated goal/goal_graph_execution approval. Existing Graph runtime will distinguish this issuer, preserve its original Factory root task and Grant, and reuse the same scheduler, validation/capture jobs, Owner decisions and task acceptance history. Factory scope revoke/cancel/expiry and unknown recovery remain effective throughout.

One table at schema15 will bind each child Graph run to its Factory scope/run/target/parent/ancestry, exact saved plan reference, policy digest, immutable derived scope/snapshot, caller provenance and ordered journal receipt. Original Goal/Graph records remain unchanged unless explicitly marked Factory-derived. Complete messages stay within the existing 1MiB envelope; raw plans keep262144 bytes and history uses bounded metadata refs.

Owner methods: factory_child_goals.start/get/list/cancel/advance_plan. Start params FactoryChildGoalStart {scope_id, request:{task_id,plan:FactoryChildPlanRef,expected_factory_run_revision}} plus outer expected_revision=scope CAS and original idempotency key. Scoped fixed execute_child_goal takes only request; Core supplies scope/caller/lease/fence. Get/list use FactoryChildGoalQuery; list returns bounded FactoryChildGoalView metadata (no raw plan duplication). Cancel/advance DTOs will be frozen before parallel bridge implementation; no generic IPC capability.

Policy fields and public start/query/view DTOs in factory.rs are frozen initially; further public changes require notifying Root. max_nodes≤planning.max_nodes and originalGrant.max_children+1, max_runs/task and total limits, root/project budgets narrower than reviewed Factory budgets, require_owner_acceptance=true. Full original planning outputs/definitions/criteria plus separate execution binding are displayed in Native scope review. No new model, identity, connection, recipient, host, workspace or paid resource.

## Schema15 / issuer contract

The draft migration in factory_child_goal.rs rebuilds goal_scopes and goal_runs with identical columns/values/indexes, removes only id→approval_proposals FK, adds factory_child_goal_runs with real original Factory and saved-plan FKs/unique receipt/digest/raw bounds, and runs foreign_key_check before commit. Foreign-key enforcement is restored on success and failure; an existing private pre-v15 backup is created first. This is not permission to accept orphan native rows: every unmarked native scope/run still verifies the original consumed native proposal/result/ordered confirmation and run authorization, unchanged. A derived row must verify the real Factory native confirmation plus exact policy digest, raw plan/history commitment, root Grant revision, parent lineage, caller attempt/fence and ordered atomic provenance.

GraphAuthority is a private typed runtime value (Native or Factory-derived), not an ApprovalProposal forged to fit old code. Each API must verify issuer from durable sources before returning authority; absence/tampered/foreign/inconsistent origin refuses. Native generic mutation APIs must not reinterpret a derived scope/run as legacy native consent. Native Owner graph-node acceptance remains its existing exact candidate/criterion private approval.

Plan identity and execution authority use separate digest domains: exact saved raw GoalPlan bytes/revision and planning digest are retained; a newly derived execution token independently checks original Grant ceilings, full execution policy and cumulative remaining reservations. No plan normalization or revision renumbering may be used to hide edits. Import must verify all earlier raw revisions before adopting the selected revision. The Factory execution snapshot digest binds both the saved-plan reference and actual execution policy/lineage.

Cancel params FactoryChildGoalCancel {scope_id,task_id,goal_run_id,expected_goal_run_revision}; advance_plan params FactoryChildGoalAdvance {scope_id,goal_run_id,request:FactoryChildGoalSubmission,expected_goal_run_revision}. Both use outer Factory scope expected_revision and exact action-specific idempotency key. Advance is explicit new saved-head adoption within the same policy and run, not re-execution of completed nodes; any unknown intent blocks it. Scoped execute_child_goal starts once; later status/result is via the existing fixed task methods. No arbitrary RPC bridge.

Required actual controls: nonempty native+Factory14 migration with byte-identical original rows/FK_check/private backup; rollback/future16; old missing or corrupt native proposal/result/sequence denies; new foreign Factory/plan/policy/grant/root/parent/caller/receipt denies atomically; legacy false omits new fields/tool; exact raw plan original revisions; children0/no remaining capacity; common ancestor/root/project sessionless+ordinary attempts; actual normal/cancel/failure/unknown/restart/expiry and exact Owner acceptance. None has run for schema15 at this draft stage.

## Runtime boundaries / one target, one derived run

The unchanged goal_graph_capabilities table remains Native-only and keeps its real approval_id FK. Derived runs never insert into it. GraphAuthority has an explicit private NativeGoal/FactoryScope issuer enum; get/list, dispatch, capture/Validator, Owner approval, acceptance verification, cancellation, adoption and recovery classify from durable native capability OR explicit scope origin/provenance, and then verify the corresponding complete chain. A deleted derived row must not downgrade its marked scope/run to legacy; conflicting native+derived records refuse. Missing native Graph capability cannot be accepted by legacy methods because those now require a real goal_execution native proposal/result.

Policy max_runs_per_task is exactly1, rejected before Native approval if any other value. A target keeps one derived scope/run; in-scope rework is explicit saved-plan adoption within that original Graph and cumulative history. max_total_runs counts different Factory targets. Initial provenance is immutable; later adoption uses append-only ordered events bound to new original saved reference plus exact run/Factory CAS. No auto-revoke/new-scope workaround or budget reset.

Start only queues authority, not a worker. A live Factory MCP caller retains its actual session/lease/reservation until the existing completed-turn internal stop, actual supervisor reap, Factory settlement and input/capture proof. The Graph acquires the same workspace only afterwards through its existing atomic session/intent/lease path. Unknown or unjoined parent outcomes cannot dispatch. Factory waiting/result/parent resume uses actual Graph terminal/owned-stop/validation/Owner acceptance evidence, never queued/success labels. Ordinary sessions remain blocked from the private Factory target path. Root/project accounting is charged once in the existing Graph ledger; additional Factory ancestor checks reference that same attempt, and unknown retained records cannot refund or reset limits.

Migration distinguishes raw transactional preservation from legitimate subsequent recovery. Before dropping old identity FKs it verifies every historical Native scope's consumed proposal/result and every Native run's original kind/result/CAS/ordered authorization/adoption chain, without requiring live TTL/input readiness. Existing native corruption refuses migration. Transaction pre/post FK_check remains an additional integrity control. Store::open recovery may legitimately mark active work unknown; this is tested separately, never suppressed to manufacture row equality.

## Explicit bounded rework and original planner recovery

Root selected the existing Factory planner recovery path, not extra MCP authority for every Graph worker. Only a newly complete Native execution scope may declare nonzero reworks. Factory selection root/project reworks exactly match corresponding execution-policy root/project values, each≤attempts−1; root also≤planning max_revisions−1, and the existing narrower root/project rules still apply. Old false and planning-only scope budgets remain hard0; no receipt/Grant is upgraded. Delegated target budget may only narrow the original same-family caller budget, including reworks. Actual admission/adoption will atomically check shared root/project and every Factory ancestor's retained reworks and attempts before a new recovery action.

After a genuinely failed Goal with every relevant Provider session and intrinsic/capture worker actually joined/reaped and no retained unknown effect, the original Factory planner may resume as a new ordinary Factory attempt under the same approved connection/config/identity/Task/scope/Grant, new actual lease/fence and fresh input observation. It receives the real failed current plan ref, original observations/failure/evidence cursor. It can submit a new original raw plan and invoke fixed advance_child_goal for the SAME Graph run using append-only adoption receipts/CAS; current parent must stop before Graph takes the workspace. Cancel-pending, unjoined, unknown or exhausted budget never trigger this recovery. Owner decisions bind each new candidate/criterion/version again. This lifecycle is still being implemented, not a claim of completed execution.


## Exact stop, single rework charge and append-only adoption source

Use a private non-Deserialize stop proof across every materialized historical Node, reservation and Graph job, with aggregate SQLite bounds before decode. Validate real ordered Provider stop, independent Capture started/joined or genuine not_started, Validator intent/receipt and Owner source. Never infer all-stop from blocked/failed/producer join. Confirmed current failure has an exact persisted proof digest and evidence cursor; unknown metrics/effects or unsettled jobs retain their original reservation/fence. An unstarted original Factory planner is explicit and distinct from a joined one.

Reserve a bounded rework cycle before preparing the original planner's new attempt and before preflight. Count original Native Goal reworks plus Factory reservations under common project/root and every Factory ancestor, once. The same-run adoption references this reservation instead of charging it twice or refunding a failed launch. Existing generic BudgetLimits::valid still caps reworks at1000, with narrower attempts−1/matching and planning max revisions bounds. Current original Grant never changes. The original source row/snapshot/initial raw plan remains immutable. New adopted saved references have separate ordered source/CAS/action-idempotence receipts, preserve raw history, retain old Node/candidate/Owner versions and initialize all new-version Nodes without reused acceptance. Complete future history/View bound is checked before writes; oversized messages are rejected, never truncated.

Execution uses the existing Factory MCP private credential (server-written optional execution flag only for a new approved execution scope), same Provider/Graph/DataWorkers/leases. Graph workers receive no extra Factory identity. New execution-only status/TaskRequest read fields supply the previously missing exact Factory-run CAS; no new generic management API/DSL/tool or billing surface is introduced. These are implementation choices pending actual current-source compile/lifecycle/migration verification, not completed acceptance.
