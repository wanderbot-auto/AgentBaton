# 12 · 已确认决策与验证待办

Design v0.2 对本轮对话的决定做了正文和机器可读同步，不只追加勘误。27题已回答；此前D01/D02也已明确。本章是产品语义的权威记录；实现完成度仍为未实现。

## 1. 决策总表

| ID | 内容 | 已确认的产品行为 |
|---|---|---|
| D01 | 单一主入口 | AgentBaton 是受管任务唯一主交互入口，App 内完成对话、执行过程、审批、接力与验收。不内嵌通用终端，不观察/接管 Ghostty 等外部 Agent 会话；仅提供在外部终端打开工作区等辅助操作。 |
| D02 | 托管环境与配置所有权 | 默认独立托管环境＋选择性导入原生配置。程序来源与配置来源独立；Baton 管理版本或复用本机程序均可。正式保留高级原生配置连接，外部配置只读、不默认写回或双向同步；身份与程序、项目、配置分开，不擅自复制认证。 |
| D03 | 目标驱动自动执行 | 用户批准目标、权限、预算和验收条件后，自动规划、拆解、选择执行者、接力、验证与返工；范围内尽量不打断用户。超范围、重大不可逆变更或实际阻塞才请求决策。 |
| D04 | 完整本地历史与清理 | 完整会话、工具事件、执行日志与结果保存在本地；按项目保留期限或永久保留，敏感项目可关闭正文。到期清理详细正文/日志，不删除源文件、采纳成果、单独报告；摘要和验收记录另行保留。 |
| D05 | 执行主机与自动路由 | 支持本机及用户配置的远程 macOS/Linux 主机，不自动创建云资源。新任务按授权、数据位置、Agent可用性和负载选主机；运行中不擅自迁移。 |
| D06 | 正式Provider与扩展 | 正式维护Codex、Qoder、Claude Code；支持自定义ACP Agent接入，按实际兼容能力开放。正式目标不等于当前已验证成功。 |
| D07 | ZCode命名专用支持 | 不额外承诺未明确发行方的ZCode专用驱动；用户可通过自定义ACP路径接入符合要求的实现。该项作为扩展候选归档，不阻塞既定完整产品。 |
| D08 | 桌面平台与最低版本 | macOS桌面正式支持Apple Silicon和Intel；最低macOS版本由依赖和真实测试确定，不为旧系统牺牲核心功能。不据此承诺Windows/Linux桌面客户端。 |
| D09 | 开源与商业政策 | 本地核心开源且独立可用，增值能力可以商业化。强调开源核心修改/分发的改进回馈；商业模块边界单独划定。 |
| D10 | 语言与界面 | 中英文切换，默认随系统；代码、命令及原始日志保留原文。专业开发工具风格、分层呈现，默认显示目标/关键进度/注意事项，详情按需展开。 |
| D11 | 预算 | 项目默认预算＋任务覆盖，限制运行时长、并发、返工/子任务等，达硬上限保存进度、暂停并通知，不自动突破。 |
| D12 | 工作流编辑 | 目标自动生成流程与执行图，允许调整步骤、执行者和验收条件，并保存模板。完整自由拖拽设计器不是已批准需求。 |
| D13 | 后台与登录启动 | 任务独立后台运行；关闭/退出界面不中止已授权执行，另设停止任务并完全退出。登录Mac后自动启动后台，不强开UI，恢复连接先对账。 |
| D14 | 兼容程序更新 | 在用户批准的更新策略内自动维护Baton独立安装的兼容版本，新版本用于新任务，活跃任务固定原版本；不改用户原生安装。 |
| D15 | 项目数据授权 | 按项目预先设定允许数据和接收方；范围内最小必要交接自动进行。新增接收方或扩大数据范围需要批准，继承不等于无限外传。 |
| D16 | 经验提炼 | 自动提炼Skill、模板和规则候选，可批量审查；确认后才启用，不直接更新项目或全局生效规则。 |
| D17 | 任务与快捷对话 | 任务为主，保留与指定Agent的快捷对话；讨论可转为正式任务，转化时按既定策略解析任务合同，不擅自扩大权限。 |
| D18 | 独立工作区 | 编码任务默认在独立工作区开发与测试，并行写任务各自隔离，通过验证后按授权合入目标分支，不直接改用户当前工作树。 |
| D19 | 验收、合入与发布 | 达到批准验收条件自动验收并合入授权目标分支，失败自主返工、无法解决冲突再问。按项目授权自动推送、创建PR和部署测试环境；生产发布单独确认。 |
| D20 | 多个具名连接 | 同种Agent支持个人/工作等多个具名连接，项目绑定默认连接；任务运行中不静默切换账号、配置所有者或计费方式。 |
| D21 | 项目配置导入与继承 | 首次导入时检查、合并项目Skills/MCP/Hooks并一次性确认，随后按批准规则托管运行；仅新增高风险能力、扩大授权或无法解决冲突时询问。项目内容和Agent输出不是新的授权来源。 |

D07为非阻塞扩展候选，既定范围是D06，不再要求用户反复确认ZCode发行方。其他条目是产品行为批准，不是执行凭据、资金或仓库写入授权。

## 3. 无需再进行同一轮选择

不重新询问已确定的主入口、配置所有权、远程系统、双架构、语言、任务自动化、发布批准边界。工程实现细节通过ADR决定，只有改变已批准产品语义、授权、隐私或商业范围才回到用户。后续每次确需产品输入时最多提出3个短问题。

## 4. 仍需验证/审定，不等于产品方向未定

- 最低macOS及远程Linux具体发行版/架构：依赖与真实设备/Runner验证后登记。不能擅自删掉Intel支持。
- CLI/adapter/协议、隔离与认证机制：按版本测；组织策略保留，配置根目录不等于安全沙箱。
- 预算、空间、性能阈值：工程测量与可配置默认，不将schema样例值变成产品默认。
- 许可证：回馈改进的政策已定，具体许可文本与增值模块边界需正式审定；无LICENSE意味着未授予发布许可，不是默认MIT。
- 凭据、真实仓库、执行预算、Host范围、分发权利和签名：真实执行前配置；不能从本设计中假造。
