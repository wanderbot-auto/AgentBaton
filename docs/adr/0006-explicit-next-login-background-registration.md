# ADR0006: explicit next-login per-user background registration

Status: implemented source slice, local Linux evidence reviewed separately; macOS and lifecycle acceptance pending. Designv0.2 / D13 / AB-SES-008/010 / AB-START-001. Original engineering draft: /tmp/background-service-native-ADR.md; implemented Native3db, UI214, composedbb5. This reversible mechanism choice does not change the full design, minimum supported OS, signing policy or authorization.

Use a fixed per-user LaunchAgent with RunAtLoad=true, KeepAlive=false, Aqua session and Background process type. Three no-argument Native commands observe, enable or disable only future-login registration. Writes require the existing Native caller/parent verification, explicit Native confirmation and fresh Layout/Snapshot comparison. No launchctl, shell, current daemon start/stop, Agent dispatch, Grant or DB mutation is added. UI text states next login and that disabling does not stop current tasks. Default is disabled. current_daemon_action is always none and effective_login_start is always not_observed; registered is not an OS-loaded/running claim.

SMAppService was not selected for this increment: it requires macOS13+ availability and a new helper/signing/FFI/bundling contract absent from current dependencies. Existing10.15 bundle metadata is not actual minimum-OS support evidence. Both architectures and the final minimum remain governed by the validation gates; this decision does not silently drop Intel or choose a final license.

Obtain the euid account home with bounded libc getpwuid_r, verify uid and HOME agreement without hand-written Darwin ABI. Reuse exactly the locked libc0.2.191 version/checksum through one direct Native dependency. Derive only the sibling batond in the current safe .app bundle; reject translocation, development layout, custom runtime and changed installation. The default runtime must already exist and be private0700, with no symlinks or unsafe owner/ancestor permissions; observe never creates/repairs it. Full directory identity participates in precommit CAS; an observed postwrite replacement yields unknown/reconcile_required rather than applied.

Open directory components descriptor-relative O_DIRECTORY/O_NOFOLLOW and recheck identity; only root-owned sticky shared ancestors receive the existing exception. Private owner state is0700, files0600/single-link; unknown contents, links, directory replacements and nonprivate files are never silently repaired. Exact shell-free plist XML escapes reserved characters and rejects XML1.0-disallowed control characters and U+FFFE/U+FFFF, while Chinese/emoji remain supported.

Write an exact private owner receipt before installing a complete plist with atomic no-replace rename. A receipt alone observes disabled and remains ownership evidence after disable; only a new explicit confirmed enable may complete matching receipt-only state. Revoke by quarantining the known plist privately, verify its identity/content after the owned rename, and restore without clobbering if a race occurred. Retain unknown quarantine and never delete unknown data as rollback. Known partial changes return partial/confirmed; uncertain mutation/lost worker result returns unknown/reconcile_required. The strict UI requires manual refresh and never automatically replays a write, including after remount.

The setting does not promise a time-bounded OS transaction, filesystem isolation from every process sharing the user, permanent installation-path immutability, instant service takeover, sleep execution or crash recovery. Menu-bar/stop-all/full-exit/task survival and full single-writer recovery remain separate unfinished acceptance. Cloud tests modify only generated private fixture trees, never actual OS service state or user home. Linux Native tests and mocked UI tests pass atbb5; actual macOS branches, real settings IPC/confirmation/login activation and dual installers remain NOT_RUN. See the exact failures, corrections and source-bound results in ../execution/background-login-registration/EVIDENCE.json.
