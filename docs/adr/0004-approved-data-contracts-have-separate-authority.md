# ADR 0004 — Owner-approved data contracts use separate authority

AB-START-001 permits the full product. This unit follows schema6 artifact integrity (PR10,3c1cd1a) and reviewed builtin.data-json-table.v1 (sourcecbd5509/docs a088529). OWNER001/002 remain acknowledged. Requirements AB-VAL-003/004/006/009/010/011 and AB-DOM-004/008 remain partially implemented until their full workflows are verified.

Use separate schema7 data_validation_policies/data_validation_runs and narrow data_validation_policies/data_validations IPC namespaces. Reuse confirmed-stop, root/attempt/spec/input and workspace-fence guards. Keep integrity-policy/history lists separate so legacy integrity approval cannot gain data-validation authority. Native approval kind data_validation resolves and displays the full server-derived contract; no renderer-approved flag or finalize route exists. A view, serialized rule or Agent statement is never an approval token.

The deterministic library checks a bounded fixed JSON table with schema/types/ranges, approved metadata and exact file bindings. Integer uses signed integer representations; Number uses finite binary64, including its rounding. The UI accepts safe integers only and rejects unsupported wider values instead of rounding. Dataset population, units and timezone are approved declarations to match, not independently proven population, physical dimensions or timezone database facts. Fixed input, script and environment hashes support provenance; no script or analysis engine executes. Sample scope cannot be upgraded to a whole-population claim.

A passed result is contract_passed with scope data_contract_only, correctness approved_schema_ranges_metadata_only, task_acceptance not_established and integration_authorized false. It neither accepts algorithms/whole tasks nor drives Git adoption or deployment. Later separately approved code/reproduction validators, integration-candidate checks and orchestration remain required; this unit does not reduce the full design.

Migration7 retains old data bytes and private pre-upgrade backup. Receipt+journal/idempotency are atomic; revocation blocks new runs but preserves historical same-key replay. Lists check raw count/bytes before JSON decode. Unknown UI outcomes retain the exact payload/key/revision and require fresh scope-valid reconciliation plus an explicit retry. Forms are folded in the existing task Artifacts view, preserving the single composer and Quiet Canvas navigation.
