# 09 · 测试、构建与发布设计

## 1. 验证分层

| 层 | 测什么 | 不能据此声称什么 |
|---|---|---|
| Unit | 状态机、合并、解析、规则、幂等、授权 | 真实 Provider 可工作 |
| Contract | ACP/原生消息、模拟 Provider、异常、schema | 真实账户和服务已验证 |
| Integration | daemon、DB、进程、IPC、产物、配置事务 | macOS 系统体验已验证 |
| Browser UI | React、可访问性、交互、事件渲染 | Tauri 原生桌面通过 |
| Native desktop | 实际 Tauri app、IPC、窗口、操作路径 | 个人真实 Agent 环境通过 |
| Provider real | 锁定版本、最小账户下完整实际任务 | 所有版本和账户均兼容 |
| Manual macOS | 安装、受管交互、权限、通知、睡眠、托管/原生连接 | 未测其他平台也通过 |
| Release security | 签名、公证、更新、依赖、无测试后门 | 软件没有任何漏洞 |

## 2. 云端与本机职责

Codex Cloud 负责仓库开发、代码检查、可运行的 Linux 侧测试和记录。官方 Cloud 环境为每任务提供工作区；重要成果需要提交/PR和可持久追踪记录，不能假设跨任务共享未提交改动。[S01]

GitHub Actions 的 macOS runner 执行原生构建、平台测试与打包。runner 标签、架构、权限与费用在配置时核实锁定，不能把“有 macOS runner”推断成已具备真实用户登录态或可稳定执行任何 GUI 测试。[S16]

用户 Mac 验证原生 CLI 账户、实际配置、外部工具打开工作区、系统弹窗和硬件交互。云环境缺少授权时提供可运行测试清单并标 not_run，不伪造成功。

## 3. Tauri 原生 UI 测试

v0.1记录的Tauri文档参考路径为 WebdriverIO 与 `@wdio/tauri-service`，其 embedded 路线支持 macOS；直接 `tauri-driver` 路线不能被当作同一项 macOS 支持。[S15]

方案以实际桌面二进制测试为独立测试层，测试插件通过编译 feature 与 CI artifact 类型隔离。**面向用户发布的生产包必须不包含内嵌测试服务器、任意 IPC 执行入口或测试专用权限。** CI 检查 bundle、features 和监听端口，防止测试便利成为后门。

即便文档支持，采用的插件版本、runner 图形环境、权限和签名仍须实测。失败应降为“该层未验证”，不能用浏览器截图替代。

## 4. 必测场景矩阵

Provider：启动失败、认证过期、协议不兼容、未知字段、审批拒绝、输出乱码、超大输出、取消无确认、原生恢复不支持、CLI升级。

Capability：同名覆盖、全局与项目冲突、注释/未知字段保留、损坏配置、外部编辑竞态、部分写入、崩溃恢复、凭据缺失、独立诊断与当前会话不一致。

Handoff：schema 错误、输入变更、重复提交、父子循环、并发槽耗尽、输出路径逃逸、产物为空、模型谎报完成、验证失败、只读输入配可写产物、失败后重试。

Recovery：daemon 崩溃、UI 重启、系统休眠、磁盘满、数据库迁移失败、进程身份变化、事件乱序/重复/缺口、未知外部副作用。

Security：恶意仓库指令、MCP tool description 注入、恶意报告 HTML、ANSI 控制、秘密日志泄露、越权委派、审批重放、跨项目输入泄露、不可信插件。

## 5. 测试数据

使用合成仓库、模拟配置和合成数据；包含坏格式、中文/空格路径、符号链接、超长输出和大型事件流。真实 Provider 测试限最小测试项目与明确预算，不使用用户生产密钥或私人数据。

固定随机种子、环境版本、validator hash 和输入 revision。数据分析断言包括单位、边界、空值、随机误差容差；代码测试包括基线、变更后、整合后。标注 flaky 原因，不以重跑直到绿掩盖失败。

## 6. CI 工作流设计

建议分为 check、core-integration、desktop-macos、provider-real、release 五类。普通 PR 无秘密；真实 Provider 与签名走人工授权/受保护环境；fork PR 不获得 secrets。每个 job 关联 commit SHA、锁文件、工具版本、命令和产物 checksum。

PR 是变更证据，CI 是验证证据，Release 是分发证据。CI 失败不会自动唤起开发 Agent，除非明确配置受控触发器。自动修复需防循环、限制尝试、范围与成本，记录触发来源；没有触发器时显示需继续任务，不许暗示后台自我修复已存在。

## 7. 发布与更新

发行优先考虑 Developer ID 签名、公证、DMG/APP 与受签名保护的更新；相应流程由 Tauri/macOS官方路径实现和验证。[S18] 开发测试包清楚标示未签名状态，不建议用户全局关闭系统保护。

D08已确认Apple Silicon与Intel双架构；最低macOS由核心依赖与实际测试确定并登记。不能因一个runner缺失就删除Intel或假定Rosetta等于真实x86验证。支持范围宣传前必须有相应构建与测试证据。安装包名称包含版本、平台与架构；发布记录包含 commit、测试摘要、已知限制和校验值。CI artifact 不等于正式发布。

更新不得中断活动尝试或破坏本地配置；数据库先迁移检查与备份，支持可解释失败恢复。自动更新只信任批准发布源；Baton管理的Agent按兼容策略更新至新任务使用，不改原生安装，不替换活跃任务二进制。

## 8. 人工验收包

每个候选交付包含安装包、commit/schema/provider版本、安装说明、测试报告、未测项、回归清单、已知问题、脱敏诊断收集方式和回退说明。用户无需阅读全部实现才能判断能否使用。

验收表按需求 ID：安装启动 → Provider诊断 → 注册项目 → 会话/审批 → Skill/MCP来源 → 配置预览/回滚 → 编码/数据接力 → 取消恢复 → 远程路由/重连 → 后台生命周期 → 数据导出删除。

## 9. 完成证明

仅编译成功不算功能通过；仅 Agent 说通过不算验证；mock 不算 real；旧 SHA 的 CI 不算新提交通过；未生成的 dmg 不能写成已交付。测试报告必须保留 passed、failed、blocked、not_run 和适用环境。

## 10. v0.2新增必测场景

两个具名连接不串账号/历史；托管模式不改全局配置、原生模式不写回；外部程序升级可探测；版本更新不改变活跃attempt；项目Hook/MCP导入批准与高风险变化；90天工作默认及项目覆盖/永久保留/敏感模式清理；记录删除与索引/缓存一致；App关闭/退出与daemon持续执行；登录启动幂等；本机断线但远端仍在执行；远程重复投递与lease过期；候选自动合入与并发目标变化；批准测试部署不允许生产部署；生产批准后改动产物导致批准失效；项目预算总量不会因分拆子任务重置。

对最低macOS、Intel与Apple Silicon分别建立依赖可编译、原生启动、Provider、密钥存储、后台服务及更新验证矩阵。尚未运行的组合写not_run，不把技术验证委托解释为最低版本已确定。
