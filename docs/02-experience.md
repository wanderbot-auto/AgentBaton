# 02 · 信息架构与交互设计

## 1. 界面组织

主导航建议为 **工作台、任务、能力、历史**，Agent 安装与项目详情在上下文内管理；设置置底。避免把每个底层模块都变成一级菜单。

桌面结构采用“项目/会话索引 — 当前工作 — 证据/上下文检查器”。菜单栏面板只显示需处理事项、运行数、快速委派与打开主窗口，不复制全套导航。全局命令面板可搜索项目、会话、任务、能力和操作。

工作台以用户工作为中心，不是三个厂商聊天框。一个任务内可出现多个 Agent；一个会话可顺序关联多项任务，但必须标明当前执行绑定。

## 2. 页面规范

| 页面 | 主信息 | 主要操作 | 必须处理的空/错误状态 |
|---|---|---|---|
| 首次启动 | 本地原则、授权范围、发现方式 | 选项目、选 CLI、连接测试 | 无 CLI、路径不在 GUI PATH、未登录 |
| 工作台 | 需注意事项、按项目会话、运行任务 | 跳转、创建、取消、委派 | 事件信息过期、daemon断开 |
| 任务详情 | 目标、执行图、当前尝试、产物、证据 | 修订、重试、审查、采纳 | 失败、未知副作用、输入变化 |
| 能力中心 | Skill/MCP 矩阵、来源链、状态 | 对比、诊断、profile、变更预览 | 版本不支持、配置无效、秘密不可读 |
| 会话详情 | 接入模式、模型/模式、事件、审批 | 消息、审批、取消、恢复、能力差异 | 能力不支持、连接中断、未知执行结果 |
| 配置变更 | old/new diff、影响范围、备份 | 批准应用、取消、恢复 | 文件被外部修改、部分应用失败 |
| 历史/证据 | 任务与版本、验证记录、导出 | 筛选、重开任务、脱敏导出 | 产物已删、验证已过期 |
| 设置 | Provider、终端、授权、留存、更新 | 明确保存、诊断、撤销 | 不可用权限、迁移失败 |

## 3. 会话卡片的信息优先级

第一行：项目/任务名 + 必须处理状态。第二行：Agent、具名连接/配置所有者、执行Host、workspace/branch。第三行：最近可信事件与时间。次要详情：Provider 版本、observed_at、confidence/source、支持的操作。

状态不能只靠颜色；使用文字、图标与时间。`未知`不是错误的同义词。`推断运行中`需要解释依据，`需要审批`只能由明确事件产生。过期阈值是可配置规则，并在状态旁显示失效原因。

## 4. 交接向导

首次目标授权和项目策略建立时展示目的、接收方、输入、输出、验证和权限。后续范围内交接自动执行，面板用于可追溯展示而非每步强制确认。只有新增接收方/扩权/实质改变验收或无法处理冲突时集中询问。

确认页必须回答：为什么选择此 Agent；复制了哪些内容；哪些文件会写；哪些权限不能实际落实；可能发生什么外部副作用；成本是否可测；自动返工上限；结果回到哪里。

不默认发送全对话。允许用户勾选最近问题摘要、文件引用、测试失败、选定片段；敏感内容用明确标记，而非未经验证的“自动脱敏完成”。

## 5. 任务详情与进度

顶部显示目标和生命周期，不显示模型估算百分比。中部默认列表时间线；依赖复杂时打开图视图。每一节点可展开输入快照、执行 Agent、原生事件、产物和验证。审批从原始权限请求映射，不能用宽泛的“允许所有”代替未知权限。

执行结束后首屏突出“已生成什么 / 已验证什么 / 未验证什么 / 等待谁”。`execution_succeeded`、`validation_passed`、`accepted`分别显示，避免一句“完成”覆盖三个概念。

## 6. 能力中心

默认按当前项目过滤，横向为 Agent/会话、纵向为能力。单元格显示状态与来源证据，不是所有能力都给布尔开关。点开某 MCP：查看配置源、合并解释、凭据引用、当前会话连接、最近调用、独立诊断结果。

Skill 详情展示内容、revision、依赖、脚本清单、兼容差异和实际使用证据；默认在Baton托管层编辑；原生配置连接仅展示外部源，修改意图转为导入托管副本，不提供隐式全局写回。Profile 应用前展示各 Provider 实际生成的差异，未知字段不丢弃。

## 7. 外部终端联动

仅提供“在外部终端打开工作区”，与“在编辑器打开”“在Finder显示”并列。可选Ghostty或其他用户工具，但不自动启动另一份Agent、不转移会话、不同步审批与输入、不扫描原有Tab。

终端/编辑器可能改同一文件；Baton检测变化并重新检查验证与输入快照。打开工作区不默认向外部工具暴露秘密环境变量；源目录与隔离工作区要明确标识。

## 8. 通知、快捷键与可访问性

通知只聚合需要处理、完成、失败、额度/认证阻塞、配置漂移；同任务去重，支持免打扰。快捷键在用户可配置空间中避免抢占终端快捷键。读屏可读任务状态、列表焦点和对话结构；高对比度、动态缩放、减少动画、状态不单靠红绿。

中英文已确认，默认随系统，可手动切换，代码/命令/原始日志保留原文。专业开发工具风格，默认分层呈现；具体视觉tokens由设计验证，不能擅自改成游戏/深空风格。工程保留系统明暗与可访问性支持。

## 9. 退出与更新体验

关闭窗口或退出界面：任务继续，后台状态在菜单栏可见。停止任务并完全退出：阻止新派发，取消/终止策略明确，并报告未确认副作用。登录后自动启动后台，提供系统可见的关闭入口。

本地进程无法在休眠/关机中被保证继续；远程任务可能继续，UI标连接状态而非错误宣称任务停止。更新兼容版本用于新任务，活跃进程不切换；App/Core升级需协议兼容或排空执行，数据库迁移不假设可任意回退。

## 10. 必须保留的交互原则

每一个被禁用的操作都解释原因；每一个有外部副作用的动作都展示范围；每一个未知状态都不伪装成成功；每个失败都有下一步动作；批量操作先展示受影响对象；大日志默认摘要且可检索，不把全量 token 推入 React state。
