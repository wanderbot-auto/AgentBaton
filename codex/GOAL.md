# AgentBaton · 全产品完成目标

在 `wanderbot-auto/AgentBaton` 中，将 Design v0.2 已批准的 130 项需求按适用性实现为可运行、可验证的 macOS 产品，覆盖 WP01–WP14 的获批范围；不以 HTML、静态界面、Mock、README 或第一条工作流替代完整目标。

完成证据必须包括：

1. 每个活动需求对应实现文件、正常/失败测试、验证维度、确切提交与证据；未验证/受阻不计为通过。
2. 单主入口、独立后台、托管/原生配置连接、能力管理、目标驱动接力、工作区隔离、审批/预算/恢复、产物验收、macOS/Linux 远程主机等设计闭环真正连通。
3. 实际测试与构建：核心、存储迁移、协议契约、故障/取消、安全、前后端 IPC、UI、macOS Apple Silicon 与 Intel。浏览器和 Mock 只能证明其自身维度。
4. 可追溯的双架构开发安装包、版本/提交/校验值、运行说明、已知问题及人工验收清单；正式签名和发布另行授权。
5. 必需 CI 和独立审查通过；重大问题关闭或明确列为阻塞；所有残余范围保留，不改验收标准求绿。

若真实 Provider 凭据、受信任远程主机、签名或平台资源不足：继续其他可执行范围，输出明确受阻项与可恢复状态。此时可报告“当前授权条件下实现进展/待外部验收”，不能标记整个产品完成。

如果环境提供原生 Goal，使用本文件建立目标并读取真实状态；不支持时将其作为普通 Cloud 任务完成契约。阶段检查点不是缩小目标的交付，也不是无限续跑承诺。达到实际服务配额、不可恢复阻塞或用户暂停时保存检查点。
