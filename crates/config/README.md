# Managed configuration transaction primitive

`agentbaton-config` implements part of WP07. It does not authorize a request, parse native Provider configuration, import credentials, discover global files, reload a Provider or expose a UI/IPC API.

A trusted daemon-side registry must resolve an approved, **non-secret** managed configuration root and classify replacement bytes before calling this crate. `ManagedRoot::open(canonical_path, Ownership::BatonManaged)` requires an existing owner-only directory. `Ownership::NativeConnected` is rejected, preserving native configuration as read-only. Passing an enum is not proof of authorization; do not expose this constructor or arbitrary paths to renderer/Agent requests.

1. `plan(Vec<Edit>)` reads exact existing bytes, checks expected SHA-256 (`None` means expect missing), rejects duplicate/unsafe paths and computes metadata-only previews. The full-file replacement must be explicitly approved; unknown fields/comments are never automatically reformatted or silently stripped by this library. A caller unable to safely preserve them must refuse its own transform.
2. `apply(ChangeSet)` serializes Baton writers, checks every baseline, saves private exact backups and a versioned manifest, then writes/fsyncs private temporary files and atomically renames each file. Multi-file changes are **not** globally atomic. The returned report records each file's state; a later failure stops subsequent writes and remains recoverable.
3. `recover(id)` reconciles pending journal entries from exact current hashes. It does not replay unknown writes or assert runtime reload success.
4. `rollback(id)` verifies backup hashes and current replacement hashes before conditional compensation. External edits are conflicts and are never knowingly overwritten. Rollback of new files removes only the matching generated file.

All paths below the root are traversed relative to opened directory descriptors with `O_NOFOLLOW`; files must be regular, owner-only, single-link and bounded to 1 MiB. Paths with traversal, symlinks, hardlinks or reserved transaction names are rejected. Parent subdirectories must already exist and be private. No content values appear in previews, reports or error strings. Backups intentionally retain exact **non-secret** bytes with mode 0600 under a mode 0700 root. Secret-bearing source files require a separate encrypted-backup/credential policy and must not be passed here.

The root private directory and process are trusted. These mechanisms do not sandbox an attacker already controlling the same OS user; portable hash-then-rename cannot provide atomic CAS against a malicious uncoordinated writer under that account. Legitimate external changes present at a check are rejected; filesystem I/O after a write can still be uncertain and requires recovery. ChangeSets and persisted journals are bound to the original root device/inode; they cannot be applied or rolled back against another connection root with coincidentally identical content. A restored root on a different inode requires an explicit new plan rather than silently replaying an old transaction. Private orphaned temporary files after low-level failure require future retention/cleanup integration.

Tests use only temporary non-secret files: normal apply/restart/rollback, concurrent writers and drift, multi-file partial failure, pending crash intent, corrupted backup, native ownership/private permission rejection, traversal/symlink rejection, cross-root plan/journal rejection and bounded writes. Linux tests do not establish macOS native behavior or Provider syntax compatibility.

## Static capability inventories and immutable snapshots

`capabilities` adds a neutral, versioned **non-secret inventory** reader and resolver. This does not parse a vendor's native configuration format or assert that a particular Provider supports a precedence rule. Provider adapters still need verified format/precedence mappings and native runtime queries.

- `SourceRoot::open_approved_private(path)` pins a trusted owner-private directory read-only. `read_selected(SourceDescriptor, relative_path)` reads only that explicitly selected regular, private, single-link file using descriptor-relative no-follow access. It never recursively discovers personal directories, executes Skill scripts, starts MCP processes or performs network diagnostics. Native sources are eligible for read-only selection; there is no native writeback method.
- The inventory fixes `schema_version = 1` and an exact `ProviderRevision`. It contains named Skill/MCP entries. Skills record content/dependency/script references and declared compatible Provider revisions. MCP target executable/argument/endpoint references and credential references are opaque references, not resolved paths, secrets or executable instructions. Unknown top-level and entry fields are preserved in the private original bytes; preview includes their names and source hashes without values. Unsupported fields nested inside typed metadata are rejected rather than silently ignored.
- `CapabilitySnapshot::resolve(ResolutionPolicy, sources)` requires every source ID exactly once in explicit lowest-to-highest precedence for that Provider/version, a rule revision and a rule-evidence reference. Only whole-capability replacement or explicit duplicate rejection is supported; arbitrary deep merging fails closed. All source entries remain in the preview with replacement provenance. Registry-marked mandatory organization entries cannot be overridden. This is configuration resolution, not permission or sandbox enforcement.
- The snapshot digest binds policy, source hashes and source descriptors. Snapshots retain the original immutable bytes; `SourceRoot::verify_unchanged` detects selected-file drift without changing an active snapshot. A changed source produces a new digest; it does not retroactively claim the old runtime reloaded.
- `assess(source_id, capability_id, SessionBinding, observations, now)` separately reports configuration/enabled resolution, diagnostic success, native session availability, content-load evidence and execution-use evidence. Runtime observations need the exact nonempty, bounded Baton-global session identity from the trusted registry, Provider version, snapshot/source hash, trusted-origin classification, evidence reference and valid freshness window. Provider-native IDs may be reused across accounts/connections and must never be used as this global identity. Independent diagnostic success never establishes session availability or use. A declared Skill compatibility match is labeled `declared_compatible`, never runtime-verified.

Roots, organization constraints, policies and observation origins must come from trusted registry/adapter code. Public Rust types do not authenticate arbitrary renderer/Agent claims. No snapshot is automatically materialized, applied, reloaded or granted new privileges. A future managed configuration materializer must obtain explicit root/snapshot-bound approval and use the transaction API; external/native writeback remains prohibited.

Snapshot tests use generated fixtures only: source-layer collisions/provenance, unsupported merge policies, mandatory constraints, Provider/descriptor identity, unknown-value preservation, source drift/old-snapshot retention, unexecuted script/MCP metadata, credential-reference-only validation, unsafe-root paths, evidence identity/time checks and diagnostic/runtime separation. They do not establish real Provider compatibility or active-session integration.

## Native read-only sources and Skill catalogs

`capabilities::native` adds explicit native source parsing and bounded filesystem discovery. It reads only caller-selected, canonical owner-owned roots/files; unlike managed write targets, native read-only roots may use ordinary 0755/0644 permissions. Group/other-writable roots/files, symlinks, hardlinks, traversal and known credential-file names are rejected. The trusted registry must supply source grants; opening a root does not prove user authorization. No real personal configuration or authentication directory is scanned by tests or setup.

`NativeSourceRoot::read_native` supports static subsets of official formats:

- `CodexToml`: `[mcp_servers.<name>]` command/args/env or URL/header declarations, explicit enable declarations and environment-variable references. Missing enablement remains unknown; no runtime default or connection success is inferred.
- `ClaudeMcpJson`: `mcpServers` in an explicitly selected project/user file. Remote entries require a documented transport type; a URL with missing type is diagnostic, not silently converted to a valid server. Nested project dictionaries in a user file remain opaque rather than being traversed automatically.
- `ClaudeSettingsJson`: project-MCP enable/reject declarations, environment variable names and hook event names. Native standing approvals are descriptive data, **not** AgentBaton grants; hooks and credential helper commands are never run.
- `QoderSettingsUnknown`: official documentation reviewed here confirms transport CLI operations and source file locations, but not the JSON object schema. The adapter returns `unsupported` with a stable diagnostic and preserves original bytes; it does not guess that another Provider's shape works.

Safe previews expose executable/argument/URL/credential **references**, argument counts, environment/header names and unknown field names. Their private values stay only in original source bytes, which have no public export accessor. Parser errors produce fixed diagnostics without source snippets. Sources retain exact raw hashes for drift checks and have no writeback/materialization method. A `parsed` status describes the supported static subset; it does not establish complete vendor schema validity, resolved enablement, native load/use, strict isolation or installed-version compatibility. Unsupported fields remain visible as unknown names, never silently written away.

`discover_skills` scans only immediate directories under an explicitly selected catalog. YAML `SKILL.md` metadata and local `scripts/` file hashes are read with bounded skill/file/depth/byte budgets and no-follow descriptor access. Scripts, dynamic `!` context commands, MCP servers and hooks never execute. Malformed/unsupported syntax remains diagnostic; names, descriptions and compatibility/tool hints are untrusted content, not permission grants. Source collisions remain separate evidence; Provider/version-specific resolution still uses an explicit policy, never a universal override order. The initial safe discovery subset intentionally rejects symlinks even where a native Provider may follow them, and does not implement native recursive/plugin/synced-cloud discovery or malformed-YAML repair.

Pinned official evidence, response hashes, supported-shape claims and corrected lookup/test failures are recorded in [native-sources.json](evidence/native-sources.json). Codex config/parser references use an exact official Git commit; unversioned Claude/Qoder documentation is identified by fetched response SHA-256 without inventing release refs. Source-format tests and static scans do not prove any real Provider task or active runtime capability.


Skill frontmatter is deserialized with bounded scalar/metadata visitors rather than a generic YAML value tree. Known scalar fields are limited to 4096 bytes, field names to 256 bytes and mappings to 256 fields; unknown nested values are consumed without expanding YAML aliases. Known scalar aliases are subject to the same size bounds, while sequence/mapping metadata where a scalar is required stays unsupported. Ordinary quoted `*`/`&` characters are preserved. This prevents a small source-byte budget from hiding a large alias-expanded heap. An isolated Linux test recreates a 30KB scalar with five levels of eight-way aliases under a 128MiB address-space limit; the main test process is never exposed to an OOM fixture.
